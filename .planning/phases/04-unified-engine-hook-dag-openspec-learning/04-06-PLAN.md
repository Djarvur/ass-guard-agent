# Plan 04-06 — Learning mode: ask once, remember, propose hooks

## Phase Goal

**As an** SDD practitioner, **I want** the agent to ask me once when it doesn't know how to launch something, remember my answer after a few confirmations, and propose new hooks from my repeated routines — **so that** the agent gets smarter about my workflow over time and I can revert any learned setting.

## Truths

- Implements D-16 (learned settings in a versioned `.ass-guard/learned.yaml` — git-trackable; each entry: situation, answer/action, confidence count, expiry/review date, source-turn refs, status), D-17 (ask-once-and-remember — when no pattern/handoff/hook matches, ask the user via session/update, execute the answer, record a candidate), D-18 (propose hooks from the work log — repeated manual sequences surface a proposed hook the user accepts/rejects), D-19 (confidence ≥3 to persist as active; expiry/review default 30 days; conflict-check at accept), D-20 (versioned + revertible — `ass-guard learning list` + `ass-guard learning revert <id>`; git history is full revert).
- Carries LRN-01 (ask + remember in a learned-config store), LRN-02 (propose new hooks from the work log, user accepts/rejects), LRN-03 (confidence ≥3, expiry, conflict-check), LRN-04 (versioned + revertible).
- Depends on 04-01 (the engine's `ActionAsk` action + the `EngineDecision` event — the engine routes an unmatched launch situation to the learning store; this plan provides the store + the propose logic + the CLI). The engine WIRING (engine calls `Store.RecordCandidate` / `Store.Lookup` on an ask) lands in 04-05 alongside the other engine-action wiring; here the store is a standalone, fully-tested seam.

<objective>
Ship the learning store + hook-proposal logic + CLI: (1) a yaml store (`.ass-guard/learned.yaml`, single-writer/copy-on-read, mutex-guarded mutations mirroring `session.Manager`) with `Lookup(situation) (Entry, found)`, `RecordCandidate(situation, answer, sourceTurnID)` (confidence 0, status=candidate), `Confirm(situation, answer, sourceTurnID)` (increments confidence; ≥3 ⇒ active; a different answer ⇒ conflict), `List() []Entry`, `Revert(id)`; (2) `ProposeHooks(worklog []WorklogEntry) []Proposal` — detect a repeated manual sequence (the same N-step sequence ≥3 times) → emit a hook Proposal the engine surfaces via ActionAsk; (3) expiry — entries past `Expiry` are ignored on Lookup (not deleted); (4) conflict-check at Confirm — same situation + different answer ⇒ status=conflict + surfaced; (5) `ass-guard learning list` + `ass-guard learning revert <id>` cobra subcommands. All logic is pure over the store file (a temp dir per test); no network, no provider.
</objective>

<interfaces>
type EntryStatus string  // candidate | active | expired | conflict
const (
    StatusCandidate EntryStatus = "candidate"
    StatusActive    EntryStatus = "active"
    StatusConflict  EntryStatus = "conflict"
)

type Entry struct {
    ID          string      `yaml:"id"`            // stable slug of the situation
    Situation   string      `yaml:"situation"`     // the trigger/question (e.g. "unmatched:launch:webfetch")
    Answer      string      `yaml:"answer"`        // the learned action (e.g. "fresh-context", "wait:30s")
    Confidence  int         `yaml:"confidence"`    // # confirmations; active at >=3 (D-19)
    Expiry      time.Time   `yaml:"expiry"`        // default now+30d; ignored on Lookup when past
    SourceTurns []string    `yaml:"source_turns"`  // provenance
    Status      EntryStatus `yaml:"status"`
}

// Store is the single-writer learned-config store (D-16). Mutations serialize
// under a mutex; reads copy-on-read (callers never mutate the returned slice).
type Store struct {
    path string
    mu   sync.Mutex
    log  *slog.Logger
}
func (s *Store) Lookup(situation string) (Entry, bool)   // skips expired + conflict entries
func (s *Store) RecordCandidate(situation, answer, sourceTurnID string) error
func (s *Store) Confirm(situation, answer, sourceTurnID string) (Entry, error) // confidence++; >=3 ⇒ active; different answer ⇒ conflict
func (s *Store) List() []Entry
func (s *Store) Revert(id string) error

// WorklogEntry is one observed manual step (the engine feeds these from the transcript).
type WorklogEntry struct { TurnID string; Tool string; Args string }
func ProposeHooks(worklog []WorklogEntry) []Proposal   // LRN-02: repeated N-step sequences

type Proposal struct {
    HookName string; Trigger string; Steps []string; Occurrences int
}

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| operator/user → learned.yaml → engine behavior | User answers cross into persistent engine behavior; a conflicting learned entry could silently use the wrong answer. |
| concurrent engine reads → single-writer store | The engine reads + the wrapper writes; a race could corrupt the file or return a torn entry. |

## STRIDE Threat Register (canonical Phase-4 IDs)

| Threat ID | Category | Component | Disposition | Mitigation |
|-----------|----------|-----------|-------------|------------|
| T-04-07 | Tampering / correctness | learned-config conflict silently uses the wrong answer | mitigate | Confirm detects a different answer ⇒ Status=conflict, Confidence NOT incremented, Lookup skips conflicted entries (T2 Test 5/6); the operator resolves via Revert |
| T-04-09 | Tampering / race | concurrent read/write corrupts the store | mitigate | single-writer mutex + copy-on-read + atomic save (temp+rename) — mirrors session.Manager (T1); tested under `-race` |
</threat_model>
