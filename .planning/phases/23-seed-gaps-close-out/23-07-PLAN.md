<objective>
Close G-23-1: make Zed deliver ass-guard's available_commands_update advertisement for a NEW session, so /undo (and every other advertised command) reaches the agent's class-B resolver in a live editor session instead of being client-side rejected.

The confirmed root cause (bind to this): internal/acp/handlers.go handleSessionNew emits available_commands_update BEFORE the session/new response frame is written. Zed drops every session/update whose session is not yet registered, and on session/new it cannot pre-register (it learns the sessionId only from the response — zed-industries/zed#60199). The advertisement is well-formed and complete (14 commands incl. /undo, wire-reproduced) but is discarded client-side. Full evidence: .planning/debug/zed-empty-commands-advertisement.md and the G-23-1 entry in .planning/phases/23-seed-gaps-close-out/23-UAT.md.

The fix (non-binding direction from diagnosis, property is binding): emit the session/new advertisement AFTER the session/new response frame is written. The Writer is an async FIFO channel (framer.go), so an enqueue that happens after the response's enqueue lands on the wire after the response — deterministic, no timing.

Purpose: The command surface is the operator's whole entrypoint to class-B commands; with the advertisement dropped, /undo, /status and every advertised command is dead in Zed (SEEDG-03's live leg fails). Steering passed — the failure is isolated to this ordering.
Output: Reordered emission + red-green ordering regression battery at two levels + truthful comments + live-Zed operator confirmation.
</objective>
