# Plan 14-01 — Shadow-git checkpoints + undo: the no-confirmation backstop (THE phase tracer)

## Phase Goal

**As the** operator about to daily-drive ass-guard from an ACP editor, **I want** the one
unrecoverable-risk backstop (workspace undo) and the two cheap evidence checks that the cross-agent
analyses flagged, **so that** early adoption starts on a controllable, cost-predictable agent — not a
leap of faith.

**This plan's slice:** both analyses' #1 borrow (ECOSYSTEM-AUDIT §3.3 item 1 / IDEA-LANDSCAPE 🧲-1,
operator-confirmed). A no-confirmation-tier agent is safe because everything is reversible AFTER the
fact — cline shadow-git, opencode `/undo`, gemini-cli checkpointing, LangGraph checkpointer all
answer the same question the same way. ass-guard snapshots workspace file state at turn boundaries
into a shadow-git store under the ass-guard root (external git subprocess, zero new deps, never
touching the user's repo), and `ass-guard checkpoint list|restore` works from the terminal. This is
the phase tracer: it wires one path end-to-end from the turn machinery (the hook point) through the
store to the CLI, proven by a byte-identical restore.

## Truths

- Carries EARLY-01 verbatim with the orchestrator-locked invariants: store under the ass-guard root
  (`.ass-guard/checkpoints/`), EXTERNAL git subprocess, never touches the user's repo
  index/remotes/HEAD, no daemon no port, snapshot at turn boundaries on the existing
  boundary/turn machinery, `ass-guard checkpoint list|restore` terminal surface, restore proven by
  byte-identical workspace + user `.git` untouched.
- Design decisions made in-plan (gray areas, rationale grounded in the captured constraints):
  - **Store layout:** ONE shadow git dir at `<workDir>/.ass-guard/checkpoints/shadow.git` (no work
    tree of its own) + turn-addressed refs `refs/checkpoints/<sessionID>-turn-<NNN>`. ONE store per
    workspace (not per session) so `checkpoint list` shows the workspace's full recovery history —
    matching cline's per-workspace checkpoint model and the "ass-guard root" invariant.
  - **Snapshot point:** parent-turn START (immediately after `nextTurnID()`, before hooks and the
    user message) — the restore target is the pre-turn state, which is exactly "undo this turn".
    Subagent turns do NOT snapshot (they run inside the parent turn's recovery window).
  - **Exclusions:** the shadow repo's `info/exclude` carries `.ass-guard/` so the store never
    snapshots itself or the transcripts; git always excludes `.git` directories natively.
  - **Cadence/retention:** every parent turn snapshots (default ON — it is the safety backstop;
    an empty change set still commits so every turn stays restorable); retention prunes oldest
    refs beyond `DefaultKeep = 50` per store.
  - **Git isolation:** every git invocation runs `git --git-dir=<shadow.git> --work-tree=<workDir>`
    with env `GIT_INDEX_FILE=<shadow.git>/index`, `GIT_CONFIG_GLOBAL=/dev/null`,
    `GIT_CONFIG_SYSTEM=/dev/null`, `GIT_TERMINAL_PROMPT=0` and `-c core.hooksPath=/dev/null` —
    the user's gitconfig, hooks, and index can never influence or be influenced by the shadow
    store (threat T-14-01/T-14-04 mitigation).
  - **Output discipline:** the `checkpoint` subcommands print to STDERR only (the binary's
    documented stdout cleanliness — main.go's "writes NOTHING to stdout").
- The 08-09 between-turn boundary machinery is NOT modified: the snapshot hook reads turn
  boundaries (turn START), it does not redefine them. SESS-02/03 boundary writers, D-11 semantics,
  and the Projector's reset point are untouched.

## Objective

Wire the reversibility backstop end-to-end: turn start → shadow snapshot (external git, isolated
env) → terminal list/restore → byte-identical workspace with the user's `.git` untouched, plus the
invariant battery (empty/idempotent/ordering/concurrency/retention) and the gated live rollback
demonstration (real provider turn mutating a scratch repo, then restore).

Purpose: EARLY-01 — the operator's single unrecoverable-risk backstop before daily adoption.
Output: `internal/checkpoint` package, the Session seam, `ass-guard checkpoint` CLI, serve wiring,
the gated live demo.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| workspace → shadow store | the user's own files (incl. secrets like .env) are copied into .ass-guard/checkpoints/shadow.git by the git subprocess |
| CLI argv → git subprocess | the operator-supplied checkpoint id reaches a git invocation |
| serve process → system git | every snapshot/restore spawns git with an isolated environment |
| concurrent processes → store | serve-loop snapshots vs terminal restore racing on one store |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-14-01 | Tampering/Elevation | Store.Restore ref handling | high | mitigate | strict id regexp validated BEFORE any git exec; refs confined to refs/checkpoints/ namespace; no user string ever used as a refspec/option (TestRestore_RejectsBadIds) |
| T-14-02 | Information disclosure | shadow store contents (secrets in snapshots) | high→medium | mitigate | store dirs mode 0700 (TestStorePerms); snapshots stay under the ass-guard root, local-only, no network path ever; redaction deliberately NOT applied (snapshots must restore byte-identically — documented in store.go doc comment) |
| T-14-03 | DoS | unbounded store growth (large binaries per turn × retention) | medium | mitigate | DefaultKeep=50 retention prune per snapshot (TestRetentionPrune); documented operator remedy (delete .ass-guard/checkpoints/) |
| T-14-04 | Tampering | user repository integrity (the core invariant) | critical | mitigate | separate git-dir + own GIT_INDEX_FILE + GIT_CONFIG_GLOBAL/SYSTEM=/dev/null + core.hooksPath disabled; pinned by TestSnapshot_UserGitUntouched + TestRestore_UserGitUntouched at unit level and inside the gated live demo |
| T-14-05 | Tampering | symlink/checkout attack during restore | low | accept | restore content originates exclusively from the user's own prior workspace (git objects the store itself recorded); no fetch/remote ever runs against the shadow repo; git checkout/clean semantics apply; accepting with rationale — a symlink-based self-attack equals editing one's own files |
| T-14-06 | DoS/Repudiation | interrupted snapshot leaving inconsistent store | low | mitigate | commit-then-update-ref ordering (a ref appears only after its commit object exists); stale-lock steal (30s) with warning; TestSnapshot_InterruptedNeverExposesPartialRef |
| T-14-SC | Supply chain | package installs | n/a | none | no npm/pip/cargo installs in this plan; system git is a pre-existing platform dependency (darwin/linux), not a module dependency — go.mod unchanged |
