# Plan 14-02 — Compaction verify-first: the decision artifact from corpus evidence

## Phase Goal

**As the** operator about to daily-drive ass-guard, **I want** the compaction question answered from
evidence rather than assumption, **so that** adoption does not start on an unverified guess about how
the mimicked agent manages context (IDEA-LANDSCAPE 🧲-2/🧲-2a; ECOSYSTEM-AUDIT §3.3 item 3 —
"parity proves structure, not cache-hit behavior").

**This plan's slice:** EARLY-02 — verify, do not design. Scan real zcode wire captures for
auto-compact / context-eviction / `cache_control` breakpoint behavior; commit the finding as a
decision artifact; route any implementation need to the post-adoption queue. Nothing is built here.

## Truths

- **Corpus reality (planning-time fact, drives this plan's shape):** the Phase-9 pinned session
  (`sess_3cee56ae`, coverage.yaml) has rotated OFF `~/.zcode/cli/rollout/` (verified 2026-08-19 —
  the dir holds only fresh 2026-08-19 sessions; the stability test's absence-skip fires). The
  analysis therefore follows a fallback ladder, recorded in the artifact: (1) the coverage-pinned
  session if it returns to disk; (2) the newest main rollout sessions present at execution time
  (planning-time check: two main sessions of 18MB/22MB exist, carrying 39/46 cache_control lines
  and tool_result forms — genuine zcode 0.16.3 wire captures); (3) NO corpus on disk → the
  analysis leg STOPS and records the blocker (the operator re-runs tools/zcode-recapture per
  docs/recapture-runbook.md) — evidence is never fabricated.
- The known 08-09 corpus facts carry forward as prior art the scan must re-verify mechanically:
  the rolling 64-message tail (46/46 tail records, session 4440f5a7) and zero mid-turn resets —
  ass-guard's Projector already implements this window; the artifact states whether mimicry
  delivers zcode's context behavior or diverges.
- What "already delivered" means here is precise: the profile + Projector window (MidTurnWindowMessages=64
  tail + between-turn lean seed D-01/D-02) reproduces the target's observable request-window shape.
- What the artifact must NOT do: design a summarization feature. If zcode shows explicit
  compaction forms on the wire, that is a ROUTED requirement (post-adoption queue), not a
  Phase-14 build (EARLY-02 is verify-first by the operator's design).

## Objective

Commit a mechanical corpus scan (code + fixtures + tests) and the decision artifact
docs/compaction-decision.md answering: does zcode emit cache_control, where; does it auto-compact
or evict context mid-session, in what observable form; and does ass-guard's mimicry already
deliver that behavior?

Purpose: EARLY-02 — evidence-based compaction decision before daily use.
