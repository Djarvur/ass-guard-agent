- DSH-03's explicit ordering: "decode spike against a real `session.jsonl.zstd` FIRST, before building the harvest on it". The real artifact arrives with 11-06's capture run; THIS plan delivers the spike code with a synthetic multi-frame round-trip (klauspost's own EncodeAll outputs concatenated — exactly dsh's per-batch frame layout) plus a skip-clean real-artifact test that flips green the moment 11-06's artifact exists. The spike's findings (frame layout, event shapes) feed the extractor in the same plan.
- The system-form decision procedure (research §3) is implemented HERE as code: count system-role messages per captured request; consistent-one → one block; consistent-N → N blocks in order; INCONSISTENT within the session → hard error (intra-session divergence — the Phase-9 stability discipline applied to dsh; classify, do not pick the nicest form).

- Research §2's failure disposition is code: ErrCRCMismatch / ErrMagicMismatch on a real artifact = STOP (corrupt or mid-write capture), never decode with checks disabled.
