# Plan 08-08 — Gap closure: capture-grounded core tool execution (the /opsx working set)

## Phase Goal

**As a** developer practicing SDD, **I want to** kick off and drive an entire OpenSpec change (`/opsx:explore → propose → apply → archive`) from ass-guard by typing the toolkit's own slash-commands, **so that** the unmodified workflow runs hands-off.

**This plan's slice:** the second blocking architectural gap surfaced by the delegated 08-07 T4 run (STATE.md Blockers, 08-07-SUMMARY "Blocking" §3). v1.0 shipped the 103-tool catalog schema-only; 08-02/03/05 implemented only openspec:*/WebSearch/WebFetch/Skill, so every Bash/Read/Write/Edit call returns `{"error":"tool Bash has no implementation yet (catalog schema authoritative)"}` — the /opsx stages' real work (file reads, file writes, the openspec CLI through Bash) is impossible and the model exhausts maxIterations adapting around the wall (89 calls, 29 unique inputs — adapting, not blind). This plan implements REAL executors for the E2E's working set — Bash, Read, Write, Edit, TodoWrite, TodoRead — with result-message shapes derived from the zcode capture corpus already on this machine (the live rollout records + the committed 08-05/08-07 fixtures), slots them into the existing catalog/DispatchBatch/RealExecutor seam, and re-runs the 08-06 gated E2E as the acceptance vehicle. It serves CMD-04 (the E2E + the 11 UAT checks behind it) and the result-content dimension of the core mimicry value (the divergence 08-07 explicitly flagged for the tool layer).

## Truths

- The fix follows the recorded disposition (STATE.md Blockers, "gap-closure plan for core tool execution, capture-grounded result formats per the zcode transcripts — same plan→checker→approve discipline as 08-07"). A fake or stubbed Bash executor is exactly the hollow green the gates exist to prevent — every executor here does the real work.
- **Tool-scope survey (honest breadth):** the 103-tool catalog = 19 core tools + 84 `mcp__*` tools. REAL today: `openspec:*` (RunGuarded subprocess, 08-03), `Skill` (per-session override, 08-05), `WebSearch`/`WebFetch` (RealExecutor backends, 08-02), `mcp__*` (MCPExecutor + host, v1.0 Phase 5), and `Agent`/`Task` (the session-layer subagent dispatch surface, v1.0 PARA-01 — routed BEFORE the batch, never through catalog Execute). Schema-only (Execute nil) remain 15 tools; this plan implements SIX — Bash, Read, Write, Edit, TodoWrite, TodoRead — chosen as CMD-04's gate need (the opsx command/skill files instruct Read ×23 and TodoWrite ×2; the captured zcode sessions show the same six carrying an SDD turn: Bash 5613/Read 141/Write 208/TodoWrite 118 calls in one subagent session) plus the obviously-core quartet. Explicitly DEFERRED with rationale (see <deferred_scope>): AskUserQuestion (hands-off: no confirmation tier — the locked safety model), EnterPlanMode/ExitPlanMode (interactive planning-mode negotiation, meaningless unattended), Cron* (scheduling belongs to the engine/hook-DAG), TaskStop (depends on Bash run_in_background, itself deferred), SendMessage/ReadSessionContext (subagent-internal communication, exercised only inside the v1.0 dispatch surface). Note: STATE.md's blocker text says "Bash/Read/Write/Edit/Grep/Glob" — Grep/Glob are NOT in the 103-tool catalog at all (the pinned profile matches the current zcode build; the older fb066d52 session predates it), so there is nothing to implement for them; the model searches via Bash.
- **Capture ground truth** (live rollout corpus `~/.zcode/cli/rollout/model-io-sess_4440f5a7…jsonl` + `…subagent_agent_8a003655….jsonl`, harvested 2026-08-15, plus the committed 08-07 fixture): tool results are PLAIN TEXT on the wire-normalized tool-role message (`content`, `toolCallId`, `toolName`, `isError`). Observed forms: Bash success = the command output as plain text, empty → `(Bash completed with no output)`; Bash failure (137/137 isError results) = `Exit code <N>\n<output>` with `isError:true`; Read = `<line-number><TAB><content>` per line, 1-based (verified against STATE.md's own line numbers), offset/limit honored; Write = `File created successfully at: <absolute path> (file state is current in the context — no need to Read it back)`; Edit = `The file <absolute path> has been updated successfully. (file state is current in the context — no need to Read it back)`; TodoWrite = a camelCase JSON echo `{"oldTodos":[…],"todos":[…],"summary":{"total":N,"pending":N,"inProgress":N,"completed":N}}`. Observed input shapes: Bash `{command, description}` (+ optional `timeout` in ms, 60000–660000 observed, schema max 600000); Read `{file_path, offset, limit}`; Write `{content, file_path}`; Edit `{file_path, new_string, old_string}` (+ `replace_all` per schema). Corpus-absent (stated, never invented): Bash output-truncation markers (none in 5700+ results; largest observed result ~70 KB passes untruncated — no cap is pinned, context safety rides the existing MidTurnWindowMessages=64 + maxIterations=64 bounds), the Bash timeout error form, every Read/Write/Edit failure form, TodoRead's result, and the default Bash timeout when the model omits the field (~60% of calls). Those follow the shipped structured-`{"error":…}`+IsError convention or a documented corpus-informed default, each flagged in code comments + the fixture for the Phase-9 re-capture to pin.
- **Bash safety = the locked model, unchanged:** no tool-execution confirmation tier (PROJECT.md Constraints: pattern/hook table + manual cancellation are the ONLY safety mechanisms — this plan adds neither allowlists nor prompts). The mitigations are the established ones: Bash/Edit/Write are catalog-mutating (DispatchBatch runs each alone-in-slot, D-21) and each opens a context boundary after completion (D-11/SESS-02); the turn ctx cancels into a process-group SIGKILL (08-03's `killGroupOnCtx` discipline: Setpgid + `kill(-pid, SIGKILL)` so wrapper-shell grandchildren cannot outlive the kill and stall Wait); the per-call timeout bounds runaway commands. Working-directory semantics: the executor runs the command with `cmd.Dir = <session workdir>` (the captured sessions' commands run at the project root; the schema has no cwd field — the session's dir is the only workdir).
- **The rendering seam is part of the gap:** executors return `json.RawMessage` (the Stub contract) and the Projector maps `Content: string(l.Output)` — so a plain-text result marshaled as a JSON string would reach the model QUOTED (`"(Bash completed with no output)"`), and a raw-text Output would corrupt the transcript's JSON. T1 lands the decode rule (JSON-string Output renders as its plain text; objects pass through verbatim — openspec/Skill/subagent results unchanged) so the captured plain-text forms actually reach the model.
- T1–T3 are fully autonomous code tasks (TDD RED→GREEN mandated); T4 is the operator checkpoint re-running the 08-06 gated E2E. This plan does NOT close the 08-06 operator checkpoint, clear the STATE.md blockers, re-seed patterns, or walk the 11 UAT checks (08-06 T3's scope — dependency handback, no duplication). Delegated authority to RUN the E2E exists (overnight entry), but the run presents evidence for operator review — the disposition stays the operator's.
