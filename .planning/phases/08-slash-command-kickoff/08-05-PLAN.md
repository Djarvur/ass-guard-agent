# Plan 08-05 — Skills, claude-code-compatibly: Skill-tool invocation + captured-shape listing merge

## Phase Goal

**As a** developer practicing SDD, **I want to** kick off and drive an entire OpenSpec change (`/opsx:explore → propose → apply → archive`) from ass-guard by typing the toolkit's own slash-commands, **so that** the unmodified workflow runs hands-off.

**This plan's slice:** the opsx command markdown bodies lean on skills (`openspec init --tools claude` installs five `.claude/skills/openspec-*/SKILL.md` alongside the commands). The user locked the claude-code-compatible mechanism: the model invokes the `Skill` tool when relevant, skill name + description reach context through the CAPTURED profile's shape with dynamic merge, and the SKILL.md loads into the turn. Commands only work if skills work — this plan is that prerequisite.

## Truths

- Implements D-04 (all discovered skills exposed — `.claude/skills/` + `.ass-guard/skills/`, existing precedence, no restriction machinery), D-05 (model-invoked Skill tool: name+description surfaced, model calls Skill(name), SKILL.md loads; NO command-referenced auto-injection — the `/opsx` prompt content itself triggers the matching skill via the model's relevance judgment), D-06 (listing shape/placement/format dictated by the captured zcode profile — ground truth in `profiles/zcode/`, never invented).
