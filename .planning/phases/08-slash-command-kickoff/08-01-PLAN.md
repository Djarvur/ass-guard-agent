# Plan 08-01 — ecosys namespaced discovery: `/opsx:*` becomes visible (THE structural blocker, first)

## Phase Goal

**As a** developer practicing SDD, **I want to** kick off and drive an entire OpenSpec change (`/opsx:explore → propose → apply → archive`) from ass-guard by typing the toolkit's own slash-commands, **so that** the unmodified workflow runs hands-off.

**This plan's slice:** the user's `/opsx:explore` invocation must first be DISCOVERABLE. Today `discoverCommands` scans `commands/*.md` flat and skips directories (`loader.go:177`), so the layout `openspec init --tools claude` actually installs (`.claude/commands/opsx/*.md`) is structurally invisible. This plan makes every namespaced command — and every same-key shadowing event — visible. It is deliberately FIRST: every later plan consumes `Registry.Commands` keys like `opsx:explore`.

## Truths

- Carries CMD-01 (one-level subdirectory scan with colon-joined keys under the existing precedence, proven by a real-fixture test generated from actual `openspec init` output) and the shadowing-warning half of CMD-05.
- Implements D-03 (everything discovered is invocable — no allow/deny machinery added here) and D-09's parse-side (frontmatter parsed for description/matching/UX, NOT acted on functionally).
- Research ground truth: PITFALLS.md Pitfall 4 (the namespace gap + collision traps), Pitfall 6 (flat-parser trap: zcode drops indented/multi-line values; a strict-YAML-only loader diverges), STACK.md §Feature 1a (zcode command rules, yaml.v3 sufficiency + fallback), FEATURES.md §(a) (zcode discovery/naming ground truth).
- zcode semantics win over Claude Code wherever they differ: name regex `^[a-z0-9][a-z0-9_:-]{0,63}$` with violators dropped silently; description falls back to first non-empty body line; command with neither description nor body is dropped; unknown frontmatter keys ignored but the command still loads.

<objective>
Make namespaced slash-command layouts discoverable exactly the way the mimicry target discovers them: extend `internal/ecosys.discoverCommands` to walk ONE level of subdirectories (`commands/<ns>/<name>.md` → key `ns:name`, colon not slash), validate names against the zcode regex, extend `parseCommand` to surface `argument-hint`/`allowed-tools`/`model` (parsed only — D-09), add a flat single-line frontmatter fallback for files that fail strict `yaml.Unmarshal` (zcode's parser is flat; accepting what zcode drops is a mimicry divergence), apply zcode's description-fallback/drop rules, and make every same-key precedence overwrite emit a stderr warning naming both file paths. Proof is a real-fixture test tree generated from actual `openspec init --tools claude` output (committed as testdata, regenerable via a documented command, re-verified live by an env-gated test when the binary is present).
</objective>
