to execute for real with capture-pinned result forms, and turn behavior guarded by a behavioral-eval
regression net, **so that** the product machinery is complete — the model never hits an unimplemented

tools. EnterPlanMode/ExitPlanMode get real state + forms with the plan-approval question riding
12-01's suspension seam; SendMessage delivers to real subagent inboxes; ReadSessionContext reads
the product's own persisted session history. After this plan the model can negotiate a plan, talk
to its subagents, and recover context from prior sessions — none of it stubbed.

## Truths

- Carries ACP-02 and ACP-03. ACP-02's "scope per capture — design at plan-phase" is resolved here
  (the design is stated in the must_haves truths + implemented in doc comments): plan mode =
  model-facing state, no enforcement tier. This is the capture-faithful reading — the captured

  tool-result-level gate, and PROJECT.md's locked safety model has no tier to enforce it with.

  text + allowedPrompts surface as the question; the reply or the D-01 timeout non-answer lands as
  the tool result. EnterPlanMode/ExitPlanMode schemas ({}, {plan, allowedPrompts?}) are never
  rewritten — Execute-only overrides.
- SendMessage's recipient space is the v1.0 subagent dispatch surface's `agent_<uuid>` ids
  (the captured schema names the format verbatim). The mailbox is per-session; delivery to a live
  agent is real (the message reaches the dispatch surface's observation point — read the v1.0
  dispatch code to find the exact seam and wire it; if the surface only tracks completed agents,
  the mailbox still delivers into the per-session record and the ack is honest about it — never
  fake a delivery).
- ReadSessionContext reads ass-guard's OWN `.ass-guard/` per-session transcripts (the D-03
  09-context per-session JSONL family) — NOT ~/.zcode (the mimicry target's private store is not
  ass-guard's to serve). Deterministic excerpting only: no LLM call inside the executor (the turn's
  model does the understanding; the tool returns a bounded, query-filtered excerpt).
- Corpus-absent forms: the captured corpus never exercises these four tools (verified: zero
  occurrences of their invocations across the surviving rollout sessions + the 08-08 harvest) —
  every form ships as the documented corpus-informed default + fixture corpus_absent flag + the
  12-05 upgrade pointer. Where the schema itself dictates shape (e.g. ReadSessionContext's
  sessionId pattern), the schema is the provenance.
- The wiring-site location note from 12-01 applies (sessionFor — grep, currently
  internal/runtime/runtime.go).
