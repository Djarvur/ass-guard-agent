# Plan 12-06 — Background work: Bash run_in_background + TaskOutput + TaskStop (ACP-05, ACP-06)

## Phase Goal

**As a** developer driving ass-guard from an ACP editor, **I want** every tool in the captured catalog
to execute for real with capture-pinned result forms, and turn behavior guarded by a behavioral-eval
regression net, **so that** the product machinery is complete — the model never hits an unimplemented
dead end mid-task.

**This plan's slice:** long-running work becomes a first-class citizen. The model can park a shell
in the background, keep working, poll or await its output, and cancel it — the ACP-05/ACP-06 pair
the CONTEXT notes are coupled (both target background work). The machinery is the TaskRegistry: one
per-session owner of background process groups, their accumulated output, and their reaping — built
on the proven process-group discipline.

## Truths

- Carries ACP-05 + ACP-06. The captured schemas pin the contracts: TaskOutput
  {task_id (required), block (required, default true), timeout (required, default 30000, max
  600000)}; TaskStop {task_id | shell_id (deprecated)}; Bash {run_in_background?, dangerouslyDisableSandbox?}.
- Corpus status: zero background-flag usage in the 08-08 harvest; 12-05's tour (wave 2, before
  this plan) is the FIRST corpus source for these forms — read its committed fixture at execution
  time and pin from it where present; otherwise the documented corpus-informed defaults + the
  corpus_absent flags stand (the ACP-07 routing, applied to this pair).
- The process-group discipline is established code: killGroupOnCtx (bash.go:87) + reapGroup
  (bash.go:109) — the registry REUSES the idiom (local mirror or shared helper within coreexec —
  prefer extracting to one place in this package if the linter permits; no cross-package import).
- The registry is per-session (D-16 isolation discipline): ids are session-scoped, never global —
  TaskStop from one session cannot address another's tasks.
- Mutating discipline: Bash remains catalog-mutating (alone-in-slot) regardless of the background
  flag — the START of a background command is still a mutating call; TaskOutput is read-only;
  TaskStop is mutating (it kills a process).
- Cap on concurrent background tasks per session: a documented bound (the schema offers no
  guidance; pick 16, document as corpus-informed default with corpus_absent flag — 12-05 may pin
  the real behavior) so a model loop cannot fork-bomb the host; over-cap starts return the
  structured error form naming the cap.
- Wiring-site location note from 12-01 applies (sessionFor — grep; currently internal/runtime/runtime.go).
