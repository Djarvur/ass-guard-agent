## Phase Goal

**As a** developer practicing SDD with OpenSpec, **I want** the toolkit's full command matrix — beyond the
proven `explore → propose → apply → archive` loop — to run end-to-end through ass-guard with zero-continue
chaining, **so that** the unmodified toolkit works hands-off, not just its flagship workflow.

**This plan's slice (the wave-0 gap closure):** the ask-suspension × chaining interaction — the NEWLY
DIAGNOSED architectural blocker that stop-and-surfaced 13-01 Task 1 (STATE.md Blockers, Phase-13 entry;
code-verified diagnosis in the iterations-20260820 README). A mid-chain AskUserQuestion suspends the turn:
`session.Prompt` returns the internal `stopAsk` marker immediately (session.go suspension branch),
`engine.Observe` exits on `stop != "end_turn"` WITHOUT deciding (observe.go post-injection check), and the
D-01 askTimeout timer resumes the turn DETACHED ~45s later (`resumeAskClaimed`, session-layer,
engine-invisible) — so in hands-off mode any mid-chain ask kills the zero-continue chain (2 of 3 completed
gate iterations died on asks; the turn eventually completes after the non-answer but nobody feeds its
completion to the engine). This breaks the 12-01 decision's own premise ("a suspended turn never chains;
the reply IS the tool result; the D-01 timer drives the same resume path") — that premise holds for a
CLIENT-driven turn but was never wired for an ENGINE-driven (injected) turn. This plan closes that gap at
its root: the resume becomes engine-visible. It serves OS-02 ("interactive dead-ends … surface via
AskUserQuestion … instead of stalling the chain") and unblocks 13-01 Task 1 (the flagship eval-gate green),
13-02..13-04 (downstream-blocked on Task 1's green gate).

- **The diagnosis is code-verified and in-repo** (iterations-20260820/README.md + iter-1/iter-4 artifacts +
  run logs + transcripts): nil RunPrompt error + no assistant_message for the asking turn + no
  engine_decision for it is exactly the `stopAsk` signature (the only stop that skips
  `AppendAssistantMessage` and the post-injection decision while returning nil error); the model asks
  nondeterministically at ANY stage (iter-1 archive, iter-4 propose). The pattern rows are proven
  discriminating wherever NO ask intervenes (commit 8c56b29) — no pattern-row change can fix this class,
  and a runner-level ask-drain or harness re-drive was already rejected (would fake zero-continue or only
  green the ask-at-last-stage shape).
- **The 12-01 ACP contract is live-proven and must survive byte-compatible** (STATE.md 12-01 Task 3 witness,
  legs d9f98023 + e253bfbd): `Session.Prompt` returns promptly at suspension (the executor returns
  ErrSuspended; the tool loop ends the turn WITHOUT appending a tool result; `stopAsk` maps to a completed
  ACP turn — the client sees the question surface and the turn's response completes, no stuck spinner); the
  operator's reply arrives as the next session/prompt and IS the tool result (captured answered form,
  verbatim); the D-01 timer (default 10m, 0 = block-forever) drives the SAME resume path with the
  corpus-absent non-answer. The engine's wait is ADDITIVE plumbing around this contract — never a change to
  it. The manager ruling is explicit: the wait happens in the engine/turn-loop layer, NOT by blocking
  `Prompt`.
- **Where the wait lives, concretely (the minimal seam):** the engine loop stops exiting on the ask stop.
  `Observe`, on `stopAsk` (first turn OR injected turn), consults the runner's OPTIONAL `AskSettler`
  capability (the ContinuePopulator precedent — additive interface, nil-safe) and blocks until the session's
  settle signal fires (either resume driver) or ctx dies; then it RE-READS the completed turn —
  `LastTurnOutput` ALREADY handles this ("an ask_suspended line is only terminal while unresolved: a LATER
  assistant_message (the resumed turn's closing text) outranks it", acp_serve.go) — and decides NORMALLY
  (table lookup, provenance, the lot). Unresolved ⇒ today's ActionAsk semantics. The resumed turn itself
  keeps running where it runs today (the reply's request goroutine, or the timer goroutine under the
  serve-lifetime ctx) — what changes is that its COMPLETION now feeds the engine instead of vanishing.
- **The serve wire contract forces ONE structural move beyond the engine wait (the park):** a synchronous
  wait inside `sessionTurnRunner.Run` would delay the ACP session/prompt response until resolution — the
  stuck-spinner the 12-01 witness verified AGAINST, and a probable protocol-level reply deadlock (ACP
  clients send the reply as the NEXT session/prompt, which they hold until the previous response arrives).
  Invariant 1 therefore requires: at suspension on the engine path, `runOneTurn` returns the prompt response
  PROMPTLY (mapAskStop unchanged) while the engine chain PARKS — the Observe continuation runs on under a
  per-session parked-chain ctx derived from serveCtx (the SAME discipline the D-01 timer already uses:
  SetAskBroker's resumeCtx — "the suspending turn's ctx dies with its prompt response"), and the parked ctx
  is ALSO cancelled by session/cancel (handleSessionCancel → cancelTurn) and session close, so D-03
  (cancellation, the only off-switch) and the no-confirmation-tier safety model stay intact. Post-settle
  injections run as server-driven turns: turn-mutex acquired per injection (12-07 queue semantics preserved —
  no two turn drivers ever overlap on one session), streaming via emitFor (the WINDOWS #3 cron machinery —
  the in-repo precedent for engine-driven turns after a client turn ends).
- **Scope fence (keep it SMALL — this is a gap closure, not a redesign):** engine-on path only — the
  engine-off path (`--no-engine` / degraded setup), the bare-session no-broker degradation, the 12-04
  plan-approval rides, and the 12-07 automation turns are untouched (automations already drive
  server-driven turns through this same machinery). No new deps; no pattern-table rows; no evalsuite bytes;
  no ACP protocol changes. If execution finds the park requiring more than (adapter suspension hook + parked
  goroutine + per-session parked ctx + turn-mutex'd injections + WaitChainIdle), STOP and surface — that is
  the "smells like a redesign" tripwire, and the manager re-rules.
