# Plan 13-02 — Zero-continue chaining over the expanded matrix (OS-02, D-03 pass 2, D-06, D-07)

## Phase Goal

**As a** developer practicing SDD with OpenSpec, **I want** the toolkit's full command matrix to run
end-to-end through ass-guard with zero-continue chaining, **so that** the unmodified toolkit works
hands-off, not just its flagship workflow.

**This plan's slice:** D-03's pass 2. 13-01 proved each command works (unseeded, manually driven) and
captured the stage closings; this plan derives the chaining seeds FROM those captures, lands them in
seeded.toml, and re-runs the matrix gate asserting zero-continue — plus the D-07 verify→fix handoff and
the D-06 flake policy. The advisory (the OTHER half of OS-02) is 13-03; the seeds here must exist first so
13-03's battery can prove the advisory does not fire on matched closings.

## Ground truth that binds

- The chaining machinery is PROVEN and needs zero new mechanism: `TurnOutput.StartedBy` + the optional
  `engine.CommandMatcher` consulted only after the dual signals miss + seeded rows (the findings-6
  disposition, live-proven in Phase 8). This plan adds ROWS, not code.
- Seed-row rules (08-06, binding): regexes from CAPTURED stage-end output only; row order among text rows
  is first-match-wins with terminal shields leading; `next` empty ⇒ generic continue prompt; bare injected
  commands inherit the FIRST invocation's arguments (scenario-subject forwarding — subjects typed on first
  invocation in every pass-2 chain).
- The D-06 flake policy is LOCKED: one re-run max, only at zero source/config delta since the failure, both
  runs recorded; two failures = hard gate failure. No best-of-N.
