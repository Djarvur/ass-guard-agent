## Planning-time probe evidence (load-bearing, verified 2026-08-19)

The pinned `openspec` 1.5.0 has NO named "expanded" preset — `openspec config profile <preset>` accepts only
`core`. The actual mechanism (verified live in an isolated-HOME scratch, /tmp/opsx-custom2): the global
config at `~/.config/openspec/config.json` (HOME-resolved; `openspec config path` confirms) carries
`{"profile":"custom","workflows":[...11 workflow names...]}` — then `openspec init --tools claude --force`
installs all 11 commands (incl. new/continue/ff/verify/bulk-archive/onboard) + their skills. Source of the
enum + key names: the installed package's `dist/core/profiles.js` (CORE_WORKFLOWS vs ALL_WORKFLOWS) and
`dist/core/config-schema.js` (profile: core|custom; workflows: array; both CLI-settable via
`openspec config set`). The operator's real config currently has NO profile key (core by default) — the
guard must restore the absent-key case exactly, not write `core` back.
