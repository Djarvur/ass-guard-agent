<objective>
Close gap G-18-1 (blocker): real sessions become enumerable — `ass-guard --resume` (and every ListSessions consumer) lists the cwd store's live transcripts.

Root cause (diagnosed in 18-UAT.md §Gaps G-18-1; do NOT re-diagnose): Manager.AppendSessionStart (internal/session/manager.go:166) has ZERO production callers, so real sessions never write the session_start opener line; ListSessions' readHeaderOpener (internal/session/list.go:273-313) requires a conforming session_start first line and therefore skips every real transcript (real transcripts begin with user_message lines). The result: "no sessions to resume" with two live transcripts on disk (~/tmp/perm-uat). Fixtures hand-write the opener, so the whole list battery is green against a shape real sessions never produce — the G-17-1 class again: tests model a fiction.

Two-sided fix per the UAT fix_direction:
(a) WRITE side — wire AppendSessionStart into real session creation: sessionFor (internal/runtime/runtime.go:1410, the sole production NewManager caller at :1454 plus the temp fallback at :1458) writes the opener as the FIRST line, sessionID in Text per the existing contract. The gate is file size: a transcript that already has bytes (resume reopens the same file through ResumeSession → sessionFor, runtime.go:1335) gets NO second opener — append-only discipline, and the opener must be first to be useful.
(b) READ side — make readHeaderOpener tolerant for pre-fix transcripts: a first line of ANY KNOWN type with a valid timestamp serves as the createdAt fallback, so legacy sessions stay enumerable. The strict session_start requirement remains the PREFERRED shape. Title scan unchanged (see Knock-on 4 below for the documented legacy-title consequence).

Purpose: restore the 18-06 D-11 picker contract (UAT Test 2) and the ACP-05 enumeration truth for real sessions.
Output: opener wired at the real creation site, tolerant listing, RED-proven pins modeling the real transcript shape, full -race battery green.
