<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| agent-file frontmatter → dispatch routing | `model:` in an untrusted repo file decides which provider/model runs — a malicious file could aim traffic at an attacker-controlled endpoint ONLY if that provider is operator-declared |
| second provider config → process | A second live provider instance loads credentials and holds breaker state inside one process |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-20-10 | Elevation | frontmatter model slug | medium | mitigate | Routing only reaches providers/models DECLARED in operator config (buildTarget errors otherwise → degrade); a repo file cannot conjure a new endpoint — the factory builds from operator cfg.Providers exclusively |
| T-20-11 | Denial of Service | second-provider lifecycle | medium | mitigate | Provider instances cached per (provider, session) — one construction per pair, not per dispatch; construction via the single factory seam so breaker/capture machinery applies; Phase 22 owns deeper lifecycle |
| T-20-12 | Information Disclosure | degrade warnings | low | mitigate | Warnings name the intended model slug and reason — never credential values or env contents (stderr posture, T-20-03 family) |
| T-20-13 | Repudiation | routing decisions | low | mitigate | D-16's durable ResolvedModel field + the D-22-verbatim args give post-hoc audit of what actually ran |

Security posture: ASVS L1; block_on=high — no high-severity threat in this plan.
</threat_model>
