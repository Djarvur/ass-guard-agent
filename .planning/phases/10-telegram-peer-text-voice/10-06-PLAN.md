# Plan 10-06 — Voice flow: download → transcribe → the transcript IS the user message (ack + auto-sent echo, no buttons)

## Phase Goal

**As a** developer away from my IDE, **I want to** drive ass-guard from a Telegram chat — full SDD scenarios over text and voice, on the same engine ACP uses — **so that** the agent keeps working wherever I am as a peer surface, not a stripped-down remote.

**This plan's slice:** D-04 end to end and TG-04's flow clause. A voice note arrives; the chat immediately shows it is being transcribed; the OGG/Opus bytes travel GetFile → download URL → Transcriber; the transcript comes back and is sent as its own chat message (the echo — you see what was heard), and THAT text drives the identical text-turn path from 10-04. If it heard wrong, `/stop` is right there. No confirmation buttons — ever (rejected anti-pattern: confirmation-tier violation).

## Truths

- Carries D-04 (locked: ack + auto-sent transcript, transcript as the user message, immediate turn, /stop as the correction path, no Confirm/Edit buttons) and TG-04's flow clauses (OGG/Opus download → Transcriber → text; async acknowledgement; `voice` AND `audio` both handled).
- Research ground truth: STACK Feature 4 (the exact download chain `b.GetFile(ctx, &bot.GetFileParams{FileID})` → `b.FileDownloadLink(file)` → stdlib `http.Get` → OGG/Opus bytes); PITFALLS Pitfall 13 (voice-vs-audio split; token-in-URL trap pointing back at Pitfall 9/10-02; async-ack recipe "bounded perceived latency"; failure posture "STT errors degrade to a stderr-logged transcript note and a user-visible message; never kill the process or the ACP frontend"; fixture-test recipe "a real tiny ogg/opus file through download→STT-stub→prompt injection"); CONTEXT specifics ("the transcript doubles as confirmation (you see what was heard)").
- Discretion decisions (documented): (1) the echo message format is `Voice: <transcript>` as a plain bot message (distinguishable from the turn output that streams after; no emoji-decorated variants); (2) the ack is ONE plain message (`Transcribing voice message...`), edited/deleted never — a second message for the echo keeps ordering trivially auditable; (3) empty/whitespace-only transcripts get a "heard nothing usable" reply instead of driving a turn (a garbage-empty prompt is worse than a retry); (4) a voice arriving while a turn is in flight gets the same turn-guard reply as text (name `/stop`) — no implicit queueing.
- The fixture recipe calls for "a real tiny ogg/opus file" — committed as testdata (a ~1-2 s silent Opus-in-OGG fixture, generated once by a documented ffmpeg command in the test's comment; the fixture bytes only assert pass-through fidelity, the fake Transcriber returns canned text).
- Hard deps: 10-04 (session registry, turn path, Frontend option surface, fake Bot API harness) and 10-05 (the Transcriber seam + typed errors).

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| remote voice/audio bytes → download → Transcriber → prompt | Untrusted binary audio becomes transcribed text that becomes model input. |
| Telegram file CDN (token-bearing URLs) → logs | The download URL is a credential carrier near every error path. |
| typed failures → chat replies | Error detail must not leak internals to the chat (stderr carries the detail). |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-10-23 | Information disclosure | token-bearing URL in logs/errors | mitigate | URL kept in a local var, never logged (Test 5); download errors scrubbed via 10-02's chokepoint before any slog write; double-net per Pitfall 9/13. |
| T-10-24 | DoS | oversized voice notes (up to 50 MB) | mitigate | bounded reader at download (50 MB); 25 MB typed cap from the backend BEFORE provider spend (Test 8); memory bounded by the read cap. |
| T-10-25 | Tampering | transcribed injection text | accept | transcript is ordinary user input — identical trust to a typed message; the engine's existing defenses (assistant-role-only pattern matching, provenance) apply unchanged; no voice-specific sanitization is added by design. |
| T-10-26 | DoS | hung transcription blocking the chat forever | mitigate | transcription runs under the per-chat turn ctx — `/stop` and shutdown cancel it (Test 10); busy flag always cleared via defer. |
| T-10-27 | Information disclosure | internal error detail in chat replies | mitigate | replies are fixed friendly strings; backend name + error detail go to slog/stderr only (Test 7). |
</threat_model>
