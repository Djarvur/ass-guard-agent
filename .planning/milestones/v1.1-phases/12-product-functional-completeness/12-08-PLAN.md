# Plan 12-08 — The behavioral-eval regression net (ACP-08, D-03; Phase 13 extends it)

## Phase Goal

**As a** developer driving ass-guard from an ACP editor, **I want** every tool in the captured catalog
to execute for real with capture-pinned result forms, and turn behavior guarded by a behavioral-eval
regression net, **so that** the product machinery is complete — the model never hits an unimplemented
dead end mid-task.

**This plan's slice:** the net itself. ECOSYSTEM-AUDIT §3.3 called the missing behavioral-eval layer
"the biggest methodological hole"; §4.4 EVAL-01..03 pins the pyramid. This plan lands it AFTER the
tool executors settle (waves 1-4) deliberately: the suite's first green run certifies the settled
behavior — landing it earlier would pin interim behavior and immediately need re-baselining (the
exact stale-expectation failure mode the 2026-08-16 drift report documented). The harness is the
Phase-8-proven gated E2E machinery, extracted to an importable package so the scenario runner, the
existing runtime tests, and Phase 13's expanded suites all consume ONE implementation.

## Truths

- Carries ACP-08 + D-03 verbatim. The gate design is locked by D-03: deterministic tool-unit tests
  in every `mise ci`; the scenario suites gate ONLY on the locked change classes (profile / model /
  turn-behavior diffs) at k=1, budgeted ~8-10 min, env-flag wired (`ASSGUARD_EVAL_GATE=1`,
  mirroring `ASSGUARD_OPENSPEC_BIN=1`); pass@k=3 is a manual/local mise task, not in the gate;
  the initial suite = the Phase-8-proven `explore → propose → apply → archive` scenario.
- The 08-06/08-09 gated E2E (`TestOpsxEndToEnd_Gated` + `TestOpsxFixableRecovery_Gated`, currently
  in internal/runtime/e2e_opsx_test.go after the extraction move — locate by grep) IS the initial
  scenario's proven flow: scratch bootstrap with the real openspec binary, zero-continue assertion
  set, capture mode, fixable-recovery probe; measured 474-505s per leg (the D-03 budget's source).
- Extraction not reimplementation: the harness logic moves to internal/evalharness (importable,
  env-gated helpers) and the runtime E2E tests keep running against it — the phase's own regression
  proof that the extraction changed nothing.
- The gate is NOT wired into `mise ci` (D-03: the scenario suites gate on change classes, not every
  commit; `mise ci` keeps its fast deterministic surface). The change-class detector is the wiring
  point: a script + mise task + a documented CI hook (the project's CI story is mise-shaped; the
  hook point is documented in the script header + README-adjacent comment, not a new CI vendor).
- Zero new dependencies (v1.1 discipline): the runner is stdlib Go + the existing test binary.
- Phase 13 (OS-03) extends the suites by adding scenario files — the scenario schema keeps that
  addition cheap (JSON in, no harness change), stated in the suite's doc comment.
