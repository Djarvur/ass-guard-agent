# Plan 12-01 — AskUserQuestion end-to-end: the model gets a real question surface (THE phase tracer)

## Phase Goal

**As a** developer driving ass-guard from an ACP editor, **I want** every tool in the captured catalog to
execute for real with capture-pinned result forms, and turn behavior guarded by a behavioral-eval
regression net, **so that** the product machinery is complete — the model never hits an unimplemented
dead end mid-task.

**This plan's slice:** the phase's flagship tool and its architecture probe. AskUserQuestion becomes
REAL: the question surfaces to the ACP client in the captured shape, the turn suspends on the engine's
ask path (the ROADMAP's locked surface route), the operator's reply lands as the tool result, and the
D-01 non-answer policy (configurable wait, default 10 min, 0 = block forever) guarantees a hands-off
run never dead-ends on an unanswered question. Everything the phase builds later (plan-mode approval,
cron engine-driven turns, the eval net's ask scenarios) reuses the suspension/resume seam this plan
proves. This is also where the "new executor" template (executor + fixture + registration + wiring
test) is re-proven for the interactive-tool class.

## Truths

- Carries ACP-01 and D-01 verbatim. D-01's timeout default (10 minutes) is the config default; `0`
  disables the timer (block forever — interactive mode). The non-answer result form routes exactly
  like ACP-07's corpus-absent forms: documented corpus-informed default now, upgraded to the captured
  form by plan 12-05's re-record if the tour captures one (per D-04's re-record-is-primary finding).
- **Surface-route semantics (locked by ROADMAP SC-1 + D-01):** the turn SUSPENDS rather than the
  executor blocking the prompt call. Concretely: the executor surfaces the question and returns a
  suspension sentinel; the session tool loop ends the turn (the ACP client receives its prompt
  response; the question arrived just before as a client-visible update); the pending ask lives in
  the per-session broker; the operator's reply arrives as the NEXT session/prompt and is routed into
  the pending ask — appended as the tool result for the suspended call — after which the SAME turn's
  model loop resumes (no new user message; the reply IS the tool result). The engine's existing ask
  path (ActionAsk / ErrAskPending — observe.go:277 "surface the ask + stop the loop") is the
  decision-level expression of the suspension: a suspended turn must never chain (the Phase-8
  pattern table would otherwise auto-continue a suspended stage — a regression test pins this).
- The D-01 timeout fires autonomously: a timer armed at suspension time resolves the pending ask
  with the non-answer form and drives the SAME resume path (engine-driven continuation). This timer
  machinery is the seed plan 12-07's cron firing reuses.
- The captured schema (questions/header/options/label/multiSelect) is byte-identical — Execute-only
  override at the per-session clone beside RegisterCore (runtime.go sessionFor, the 08-05/08-08
  discipline). The catalog entry is NOT mutating (a question reads nothing).
- Wiring-site robustness: `sessionFor` lives in `internal/runtime/runtime.go` (~:603) after the
  in-flight v1.2 Phase-10 extraction (it moved from `cmd/ass-guard/acp_serve.go`; a concurrent
  executor is completing that move). LOCATE the site by grepping for `func (r \*Runner) sessionFor`
  (or `sessionFor(` across cmd/ + internal/) and edit it wherever it lives at execution time; do not
  depend on either path being final.
- Result-form rendering rides the 08-08 plainContent seam (JSON-string Outputs render as unquoted
  plain text) — the answered/non-answer forms are plain-text forms exactly like the Bash forms.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| model → ask surface | The model authors the question/options text that reaches the operator's client |
| operator → pending ask | The reply text crosses from the client into the suspended turn's tool result |
| timer → turn resume | The D-01 timeout autonomously resumes a turn with the non-answer form |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-12-01-01 | Spoofing | reply routing | high | mitigate | PendingAsk is keyed by turnID+callID inside the per-session broker; a reply resolves only the session's own pending ask — no cross-session or cross-turn injection (Test 1 asserts the exact callID receives the result) |
| T-12-01-02 | Tampering | question payload | medium | mitigate | The surfaced payload is rendered read-only to the client; the reply is embedded verbatim into the answered form (no reinterpretation); redaction chokepoints (redact.walkRedact) already scrub string values on the transcript path |
| T-12-01-03 | DoS | model asking in a loop | medium | mitigate | maxIterations=64 bounds the turn; each suspension ends a turn (the client controls the next prompt); block-forever (timeout=0) is an explicit interactive-mode operator choice per D-01, not a default |
| T-12-01-04 | Repudiation | suspension evidence | low | mitigate | Transcript suspension record + engine_decision (action=ask) line for every suspension (the D-20 audit-everything discipline) |
| T-12-01-05 | Information disclosure | question text | low | accept | The question reaching the operator IS the product (ACP-01); no credential material can legitimately appear in a model-authored question and the redaction chokepoint covers the transcript mirror |
