# Plan 12-07 — Cron: the persisted schedule + queue/fire-once engine-driven turns (ACP-04, D-02)

## Phase Goal

**As a** developer driving ass-guard from an ACP editor, **I want** every tool in the captured catalog
to execute for real with capture-pinned result forms, and turn behavior guarded by a behavioral-eval
regression net, **so that** the product machinery is complete — the model never hits an unimplemented
dead end mid-task.

**This plan's slice:** the last tool family — scheduled work. The model can create, list, update,
and delete automations against a real persisted store, and a due prompt fires as an engine-driven
turn under D-02's exact semantics: queue-behind-active-turn while running, fire-once catch-up with a
missed-window note when the agent was down, no daemon, no port. This is also where the engine-driven
turn machinery (the same continuation seed 12-01's timer-resume proved) becomes a general capability
— Phase 13's chaining and any future heartbeat ride it.

## Truths

- Carries ACP-04 + D-02 verbatim. D-02's design decisions are locked: queue + fire-once catch-up;
  per-project JSON store under `.ass-guard/schedule/` (0600, the existing artifact family —
  EnsureGitignore already covers `.ass-guard/` subdirs, verify); `lastFired` persisted per
  automation; each catch-up firing carries a missed-window note in its prompt context; no daemon,
  no network port.
- The captured schemas carry real constraints the parser must honor: standard 5-field cron in the
  USER'S LOCAL TIMEZONE ("Do not convert to UTC" — the schema says it verbatim); delayMinutes for
  relative delays (the schema's own warning: never convert a relative phrase into a fixed clock
  time); CronUpdate requires a synchronized title when cron/prompt meaning changes (validated
  where checkable, else trusted as model-provided per the no-confirmation-tier model).
- Forms: 12-05's cron tour (wave 2) is the corpus source — read its fixture at execution time;
  absent families keep documented defaults + corpus_absent flags (the ACP-07 routing).
- Engine-driven turn mechanics: the firing reuses the per-session turn entry with a StartedBy-style
  provenance (the Phase-8 chaining machinery's vocabulary — TurnOutput.StartedBy exists for exactly
  this class of provenance); emissions go through the session's client-visible seam when a client
  is connected, and always to transcript + audit (a headless catch-up on process start is valid —
  artifacts on disk are the evidence).
- Serialization: per-session turn mutex/queue — an engine-driven firing NEVER interrupts an active
  turn (D-02's "serialized, never interrupts", mirroring mutating-alone-in-slot). The queue is
  in-memory (a firing lost to a crash is recovered by the next catch-up pass — lastFired makes this
  exactly-once per missed window).
- The store write boundary: `.ass-guard/schedule/` only (the locked `.claude` read-only rule); 0600
  perms; atomic write (temp + rename) so a crash cannot corrupt the store.
- Zero new dependencies: the cron parser is hand-rolled 5-field (minute hour dom month dow —
  including */step, ranges, lists; the schema's examples pin the surface). This is well-trodden
  ~100-line Go; no library (v1.1 zero-deps discipline).
- Wiring-site location note from 12-01 applies (sessionFor/Runner — grep; currently
  internal/runtime/runtime.go).
