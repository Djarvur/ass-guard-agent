# Plan 08-04 — Expand + turn wiring: typing `/opsx:explore` becomes a real turn (invisible expansion, durable provenance)

## Phase Goal

**As a** developer practicing SDD, **I want to** kick off and drive an entire OpenSpec change (`/opsx:explore → propose → apply → archive`) from ass-guard by typing the toolkit's own slash-commands, **so that** the unmodified workflow runs hands-off.

**This plan's slice:** the user types `/opsx:explore fix-the-thing` in Zed and the turn that runs IS the command's expanded markdown body — invisibly (the editor shows the typed command only), with the transcript recording the expanded body plus provenance, and with command-level context boundaries for mutating stages. This is where the ecosys loader (08-01) meets the Session Core.

## Truths

- Carries CMD-02 (zcode substitution semantics fed to the turn as the user message; table-driven edge-case test written BEFORE implementation; unknown `/foo` plain-text fallthrough) and CMD-05's provenance + assistant-role-only regression halves.
- Implements D-01 (typed command only — no session/update echoes the expansion), D-02 (expanded body = user message; typed command = provenance metadata for session/load replay fidelity), D-09's action-side (frontmatter parsed but NOT acted on — expansion substitutes the body only), D-11 (mutating commands open a boundary at expansion; read-only never).
- Expansion hooks at the TURN RUNNER (session layer) — NOT `internal/acp.handleSessionPrompt` (surface-agnosticity: Telegram inherits `/opsx:*` free; `internal/acp` stays protocol-pure).
- zcode semantics win over Claude Code wherever they differ (PITFALLS Pitfall 3): `${ARGUMENTS}` braces NOT recognized; `` !`cmd` `` dynamic shell NOT recognized; out-of-range positionals → empty; single-pass `strings.ReplaceAll`; substitution happens inside code fences.
- Continue-injections must expand TOO: the engine's chained next-stage prompts (08-06's `/opsx:propose …` injections) flow through the adapter — expansion is applied on that path as well, so every expanded turn (user-typed or engine-injected) gets identical provenance + boundary treatment.

The zcode substitution contract (FEATURES §(a) / PITFALLS Pitfall 3 — implement EXACTLY this, target wins over Claude Code):
- `$ARGUMENTS` → full argument string (verbatim remainder after the command token).
- `$1`…`$N` → positional (whitespace-split); out-of-range → EMPTY string (not literal, not error).
- Args supplied but NO placeholder in body → append under a `User arguments:` heading (exact heading text).
- `${ARGUMENTS}` brace form NOT recognized (stays literal).
- `` !`cmd` `` / ```! blocks NOT recognized as dynamic shell (stay literal — no execution ever).
- Single pass: an argument containing the literal `$ARGUMENTS` must NOT re-expand (one strings.ReplaceAll per token, no loops/re-parses).
- Substitution DOES happen inside code fences (no fence skipping).
