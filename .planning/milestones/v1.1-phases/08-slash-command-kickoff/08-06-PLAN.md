# Plan 08-06 — The gate: real /opsx E2E, real-output pattern re-seed, 11 UAT checks, zero continues

## Phase Goal

**As a** developer practicing SDD, **I want to** kick off and drive an entire OpenSpec change (`/opsx:explore → propose → apply → archive`) from ass-guard by typing the toolkit's own slash-commands, **so that** the unmodified workflow runs hands-off.

**This plan's slice:** the product proof itself. Everything before this plan made the pieces real; this plan drives the whole scenario against the REAL binary in a REAL scratch project with the REAL model, captures the model's ACTUAL stage-end output, re-seeds the chaining patterns from that capture (D-12 — patterns must match model OUTPUT, never command-file input), re-runs the scenario to zero-manual-continue green, and closes the 11 UAT checks that v1.0 deferred.

## Truths

- Carries CMD-04 fully (real scenario, zero continues, gated paths, 11 UAT checks).
- Implements D-12: patterns seeded from REAL `/opsx` run output captured during THIS gate; operator-overridable (TOML overlay); the existing learning mode extends for unfamiliar handoffs (no new learning code — the v1.0 store already handles asks).

- The engine's injection mechanics are v1.0-proven (Observe → ActionContinue → runner.Run(nextPrompt)); what's new is (a) the injected prompt carries the NEXT /opsx command (Decision.NextPrompt from the pattern table), and (b) the injection expands through 08-04's seam so chained stages get provenance + boundaries like typed ones.
