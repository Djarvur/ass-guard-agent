# Plan 08-07 — Gap closure: within-turn tool-result carry (mid-turn conversation assembly)

## Phase Goal

**As a** developer practicing SDD, **I want to** kick off and drive an entire OpenSpec change (`/opsx:explore → propose → apply → archive`) from ass-guard by typing the toolkit's own slash-commands, **so that** the unmodified workflow runs hands-off.

**This plan's slice:** the blocking architectural gap surfaced by 08-06's real-model gate (STATE.md Blockers, 08-06-SUMMARY "The Blocking Finding"). The Projector rebuilds an identical lean window every tool-loop iteration, so the model never sees its own tool calls or results mid-turn — real agentic turns cannot converge (failed twice: 16 and 64 inner iterations). This plan carries tool-call identity through the provider seam (root cause 1+2), gives the Shaper structured mid-turn message shapes (root cause 3), accumulates the current turn's exchanges in the Projector (root cause 4 — the blocker's recommended path, verbatim), pins the shapes against the CAPTURED zcode sessions, and re-runs the gated real-model E2E as the acceptance vehicle. It serves CMD-04 (the E2E + the 11 UAT checks behind it) and the message-shape dimension of the core mimicry value (PROJECT.md: outgoing requests structurally indistinguishable — the captured sessions carry mid-conversation tool results; v1.0 never implemented that half).

## Truths

- The fix follows the executor's recorded recommendation (STATE.md Blockers disposition): unique tool-call IDs through the provider seam → transcript records real IDs → Projector emits the current turn's assistant/tool_use/tool_result lines after the lean seed → Shaper maps structured blocks to provider-native params → parity check against a captured tool-carrying zcode request. This plan is that path.
- T1–T3 are fully autonomous code tasks (TDD RED→GREEN mandated); T4 is the operator checkpoint that re-runs the gated real-model E2E — the operator witnesses convergence; this plan does NOT close 08-06's operator checkpoint, clear the STATE.md blocker, or perform 08-06 T3's pattern re-seed + the 11 UAT checks (those remain 08-06's scope, resumed after this plan's E2E passes — dependency handback, not duplicate work).
- Capture ground truth (pinned in T3's fixture from a live rollout record): the zcode-normalized mid-turn forms are `{"role":"assistant","content":"","toolCalls":[{"id","name","input"}],"modelRef":…}` and `{"role":"tool","content":"<text>","toolCallId":"call_…","toolName":"…","isError":false}`, plus user string-content and mid-conversation system messages; `response.toolCalls[]` is `{id, name, input}` (VERIFIED-FACTS.md item #1 — the current `provider.ToolCall` dropped the id). Known corpus limitation, stated up front: the rollout records carry the runtime-normalized `request.messages` — `request.body` has NO messages key, so the Anthropic WIRE rendering of mid-turn blocks is not directly verifiable from this corpus; the wire form follows the protocol-canonical rendering `Provider.ToolResultMessage` (PROV-02, Phase-1 committed) already encodes, and wire verification rides Phase 9's re-capture (AUD-05).
- Boundary semantics are load-bearing and unchanged (D-11, Phase-2 D-01/D-02): accumulation is scoped to the CURRENT turn's lines after the later of {last boundary, the turn's user_message}; a mid-turn mutating-tool boundary (MaybeAppendBoundary) still resets the next projection to the lean seed. Existing projector tests (TestProjector_LeanSeedAfterBoundary, TestProjector_SummaryExtraction, TestProjector_FirstTurn) must stay green unmodified.
- Scope honesty (flagged, not silently dropped): the STRUCTURE of mid-turn messages is this plan's mimicry bar; the CONTENT format of tool results (zcode renders e.g. Read results as plain numbered text; ass-guard's executor returns JSON objects) is a separate divergence at the toolexec layer, flagged for Phase 9's re-capture — same disposition discipline as 08-05's Skill-result-shape note.
