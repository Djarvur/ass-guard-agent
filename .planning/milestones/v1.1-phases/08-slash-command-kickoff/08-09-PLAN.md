# Plan 08-09 — Gap closure: boundary resets move between turns (capture-faithful within-turn carry)

## Phase Goal

**As a** developer practicing SDD, **I want to** kick off and drive an entire OpenSpec change (`/opsx:explore → propose → apply → archive`) from ass-guard by typing the toolkit's own slash-commands, **so that** the unmodified workflow runs hands-off.

**This plan's slice:** the third blocking architectural gap surfaced by the delegated 08-08 T4 run (STATE.md Blockers, 08-08-SUMMARY "Diagnosis"). With core tools finally REAL, both gated E2E turns exhausted maxIterations for a NEW structural reason: every mutating tool result is immediately followed by a D-11 context boundary (42/42 Bash results in the fixable transcript; 75/77 in the explore turn), and the boundary resets the mid-turn window to the lean seed — the model cannot see its own prior exchanges within the turn, so it re-starts every iteration (the Skill `openspec-archive-change` re-read with the IDENTICAL input 60 consecutive times; 64 Skill calls / 2 unique) and never ends its turn, despite having COMPLETED real work it could not see (a real `openspec archive`, artifacts on disk). This plan re-scopes the boundary reset to BETWEEN turns: the producing turn accumulates to its end (08-07's machinery, capture-pinned), and the boundary fires when the next user message/command arrives. It revises the IMPLEMENTATION of the v1.0 SESS-04 reset timing (and 08-07's "a boundary — between turns OR mid-turn — still collapses the window" truth, which 08-08's live evidence corrected); D-11's expansion-time boundary semantics for slash-commands stand unchanged. It serves CMD-04 (the gated E2E + the 11 UAT checks behind it) and the request-shape parity dimension of the core mimicry value.
