# Plan 14-06 — The uniform tool contract: timeouts, is_error, retry discipline, flags, census cross-check

## Phase Goal

**As the** operator about to daily-drive ass-guard, **I want** every tool in the catalog held to one
uniform execution contract — bounded time, capture-faithful error marking, transient-only retries,
declared concurrency/destructiveness — **so that** no tool call can hang a turn, corrupt the error
signal, or retry what must not be retried (Claudecourse #5/#30; ECOSYSTEM-AUDIT §4.4 TOOLCON;
IDEA-LANDSCAPE 🧲-6).

**This plan's slice:** EARLY-06 — inventory the existing partial implementations (openspec
per-command timeouts, Bash model-ms timeouts, web 30s, provider Transient classification,
mutability-driven dispatch), close the gaps (catalog-wide per-tool timeouts at the dispatch seam,
is_error corpus grounding, retry-only-transient pins, the two flags), and cross-check the contract
inventory against the occ surface census (input only, per the 2026-08-19 disposition).

## Truths

- **Where the annotations live (locked):** coretools.json is the ass-guard-side annotation surface
  (the mutability precedent — 19 tools, fields `mutability` beside `description`/`input_schema`).
  New fields `timeout_ms`, `concurrency_safe`, `destructive` follow the same pattern. The captured
  tools.json (79 tools) is never touched — MCP/plugin tools get the DEFAULTS (timeout backstop;
  mutability-derived concurrency) with their explicit annotation a documented v1.2 knob.
- **Timeout precedence (in-plan decision):** a tool's own tighter deadline always wins — Bash's
  model-provided ms timeout and openspec's per-command timeout are INNER deadlines; the
  DispatchBatch annotation is the outer BACKSTOP (DefaultToolTimeoutMS = 120000). This closes the
  "no deadline at all" class (a hung executor today can hold a turn) without changing any
  captured behavior.
- **is_error grounding reality:** the shaper carries IsError end-to-end (Message.IsError →
  NewToolResultBlock) and Bash already emits the captured 137/137 `Exit code <N>`+IsError shape;
  the GAP is the cross-catalog inventory — which corpus tool_results carry is_error=true and in
  what forms — committed as evidence, with executor mismatches fixed.
- **Engine consumption boundary (in-plan decision, rationale):** the flags feed parallel dispatch
  (pool membership — D-21 semantics unchanged: mutating stays alone-in-slot) and are exposed for
  engine/audit observation. GATING engine chaining on isDestructive would revise the locked
  unmatched⇒nothing safety model — routed as an operator decision, not built here.
- **The occ clone is GONE from disk (orchestrator fact):** re-clone shallow under
  `tools/occ-census-clone/` (gitignored), pin the commit in the census fixture's provenance
  fields, never vendored.
