# Plan 14-04 — Cache-discipline probe + target-version drift warning in the parity harness

## Phase Goal

**As the** operator about to daily-drive ass-guard, **I want** cache-hit behavior observable in the
existing parity run and a loud warning when the installed zcode drifts from the pinned capture,
**so that** daily-use cost drift is detectable rather than discovered on the invoice
(ECOSYSTEM-AUDIT §3.3 item 3: "dynamic merges can be structurally perfect and still bust zcode's
cache economics"; 2026-08-19 borrow-#13 disposition: the cheap warning slice lands here, the full
nightly gate in 12-08).

**This plan's slice:** EARLY-03 — two additions to the existing parity harness: (1) a cache probe
asserting stable→volatile ordering of dynamic merges and captured cache_control placement against
the corpus pin, wired into `ass-guard parity`; (2) a target-version drift warning comparing the
installed zcode to the coverage manifest's recorded capture version — loud, never blocking.

## Truths

- The probe consumes 14-02's committed corpus fixture (the cache_control placement pin) and 14-03's
  audit conclusions on cache_control; corpus authority wins on any conflict (locked prohibition).
- "Stable→volatile ordering" is precise: the captured profile's system blocks and tools array are
  the STABLE prefix; everything dynamically merged at runtime (skills/agents listing blocks from
  CMD-06/12-02, mcp__* tools from the MCP host, hook-context blocks) is VOLATILE and must append
  AFTER the stable prefix — never splice into it. The dynamic-merge-into-captured-shape pattern
  (08-05 skills, 12-02 agents, 12-01 hook context) already appends; the probe PINS that property
  so a future merge site cannot silently regress it.
- The drift warning's two sides: pinned = coverage.yaml `target_capture_ref.zcode_version`
  (currently "0.16.3", recorded by 09-03); installed = best-effort `zcode --version` exec
  (fixed argv — no shell, no user input; a bounded timeout; absent binary → explicit skip note).
  Planning-time fact: the pinned capture session rotated off disk — the warning's VALUE is exactly
  this situation made visible (the profile's ground truth ages as zcode updates).
