# Plan 10-05 — `internal/stt`: the Transcriber seam — OpenAI default (existing client), Groq by URL swap, whisper.cpp subprocess

## Phase Goal

**As a** developer away from my IDE, **I want to** drive ass-guard from a Telegram chat — full SDD scenarios over text and voice, on the same engine ACP uses — **so that** the agent keeps working wherever I am as a peer surface, not a stripped-down remote.

**This plan's slice:** the voice half of TG-04 — everything between OGG/Opus bytes and plain text, as a standalone seam the Telegram voice handler (10-06) consumes. No new dependency for the default (the existing go-openai client already implements the multipart transcription endpoint — verified via `go doc` against the pinned v1.42.0); Groq is the same code with a different base URL; whisper.cpp stays an out-of-process subprocess per the standing no-cgo constraint. Telegram voice arrives as OGG/Opus which the cloud APIs ingest natively — only the whisper.cpp path transcodes (ffmpeg → 16 kHz mono 16-bit WAV).

## Truths

- Carries TG-04's backend clause ("OpenAI default via the existing go-openai client, Groq via base-URL swap, whisper.cpp via config-gated subprocess"); CONTEXT Discretion delegates "STT backend config surface (within the Transcriber interface contract)".
- Research ground truth: STACK Feature 4 STT table (model slugs `gpt-transcribe` recommended / `whisper-1` legacy for OpenAI; `whisper-large-v3`/`-turbo` for Groq at `https://api.groq.com/openai/v1`; whisper-cli v1.9.2 flags `-m/-f`, stock builds read 16-bit WAV only, the ffmpeg recipe verbatim; 25 MB cloud cap vs 50 MB Telegram voice); PITFALLS Pitfall 13 (ogg/opus + the audio-vs-voice split — handler side, 10-06; size ceilings; subprocess stdout capture; "comparables confirm the seams"); SUMMARY ("STT as an internal interface — no new HTTP stacks, no audio deps").
- Discretion decisions (documented): (1) Config lives in the `stt:` subtree of `.ass-guard/telegram.yaml` (loaded by the Telegram frontend in 10-06; internal/stt owns ONLY the struct + YAML tags + selection — no file I/O of its own, keeping this package frontend-free and wave-1-parallel); (2) API key rides the existing credential chain semantics (env `OPENAI_API_KEY`/`GROQ_API_KEY` → config literal) with the key NEVER logged; (3) the whisper.cpp parser reads whisper-cli's stdout transcript (plus `--output-txt`-style file when configured — read `whisper-cli -h` behavior from the research notes; keep the parser tolerant: prefer a temp output file when the flag set supports it, fall back to stdout parse); (4) `audio`-update bytes may be non-Opus containers — the cloud backends pass bytes as-is (provider validates); the whisper path's ffmpeg transcode handles container variety by construction.
- Explicitly NOT built (CONTEXT Deferred): STT fallback CHAINS (backend selection is one configured backend; the three-way chain is a Future Requirement).

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Telegram voice bytes (remote user audio) → Transcriber → provider/subprocess | Untrusted audio crosses into cloud APIs or local subprocesses. |
| STT provider responses → text injected as user prompt | Provider-returned text becomes model input (prompt-injection surface inherited from any user text — same trust level as typing). |
| api keys (env/config) → HTTP headers / subprocess env | Credentials in transit and in child-process environment. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-10-18 | Information disclosure | api key in error strings / child env | mitigate | errors wrap status codes only (Test 4); key never logged; whisper path passes no key at all (local model); config literal keys already covered by existing redaction shapes. |
| T-10-19 | Tampering | malicious audio crafting provider-side surprises | accept | bytes pass unmodified to the configured backend — that is the feature; the provider is trusted infrastructure; result text is treated as ordinary user input (same trust as a typed message — the engine's own defenses apply downstream). |
| T-10-20 | DoS | giant voice blobs exhausting memory/requests | mitigate | 25 MB typed cap BEFORE any HTTP call (Test 3); whisper path streams via temp files, not in-memory growth beyond the input itself. |
| T-10-21 | DoS | hung subprocess | mitigate | every child is exec.CommandContext-scoped (Test 5) — /stop and shutdown reach the subprocesses. |
| T-10-22 | Information disclosure | subprocess stdout corrupting the ACP byte stream | mitigate | buffers ALWAYS (Test 2 canary); no os.Stdout anywhere in the package (grep gate). |
</threat_model>
