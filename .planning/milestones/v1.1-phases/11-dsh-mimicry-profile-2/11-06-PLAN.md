# Plan 11-06 — The capture run: operator workload, census, bundle, seed

## Phase Goal

**As an** operator routing DeepSeek-model turns, **I want** a second mimicry profile whose content is captured from deepseek-harness's real wire traffic, **so that** ass-guard's requests are structurally indistinguishable from dsh's — proving the N-profile thesis with no target-specific code paths.

**This plan's slice:** DSH-03's execution half + DSH-04's seed leg — the 09-04 pattern replayed for dsh. Plans 11-03/11-05 built the machinery (proxy, zstd spike, extractor, runbook); this plan RUNS it once: the operator drives the divergence-prone workload in real dsh at a pinned commit (the one genuinely human step — it is usage of the mimicked agent), then the executor automates everything after: threshold verification from the capture file, the capture census committed BEFORE the bundle, extraction with full provenance, the real-artifact zstd spike going green, and the sanitized seed into the embedded defaults. Extraction legs never touch a credential; only the proxy's upstream forwarding needs the gateway key.

## Truths

- The checkpoint is `checkpoint:human-action` (the 1% class, 09-04 precedent): installing and driving dsh's UI is interactive usage of another agent; there is no CLI path. Everything after the capture is automated: threshold counts, census, extraction, seed — the checkpoint gates ONLY the capture itself.
- Ordering discipline (Pitfall 18 adapted): the capture census commits BEFORE the profile bundle — the census classifies what the capture shows (form decision, tools, headers, thresholds), so the bundle commit is reviewable against it. A bundle commit without a preceding census artifact is the same warning sign Phase 9 banned.
- The system-form decision happens HERE, from the real capture, via 11-05's mechanical procedure — one consistent form or STOP. This is DSH-02's "form decided from the capture, not assumption" closing its loop.
- The raw capture file (conversation content + identity header values) NEVER enters the repo: only hashes, counts, and the extracted STRUCTURE ship. The seed sanitization replaces operator-identifying header values with placeholders while preserving names — the leak-guard test in internal/defaults enforces it.
- If the capture lands below thresholds: STOP and re-invoke the checkpoint (re-run the workload) — never relax thresholds, never proceed with a homogeneous capture (Pitfall 17's rule carried to dsh).
