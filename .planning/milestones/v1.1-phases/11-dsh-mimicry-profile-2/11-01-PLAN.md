# Plan 11-01 — Zcode-ism audit + shared-code generalization (the N-profile invariant made mechanical)

## Phase Goal

**As an** operator routing DeepSeek-model turns, **I want** a second mimicry profile whose content is captured from deepseek-harness's real wire traffic, **so that** ass-guard's requests are structurally indistinguishable from dsh's — proving the N-profile thesis with no target-specific code paths.

**This plan's slice:** DSH-01. The architecture claims "N profiles, no target-specific code paths" but 69 non-test `zcode` references sit under `internal/` + `cmd/` today. This plan audits every one (Pitfall 16: the FIRST task of the dsh phase), genericizes the load-bearing ones — redaction's identity semantics become profile-supplied — documents the legitimately zcode-scoped ones (the `.claude/` compat surface), and installs a grep gate so the invariant is enforced mechanically forever, not re-audited by hand. After this plan, a second profile can flow through shared code without hitting zcode-shaped assertions or wrong redaction.

## Truths

- The census is grounded: research §6 classified the 69 refs; this plan verifies the classification against the working tree at execution time (the count may have moved with Phase 8/9/10 landing).
- The load-bearing set (research §6): `internal/redact/redact.go`'s "12 zcode identity header names" doc-contract (the walker/secretKeys are already generic); the zcode-shaped doc comments in `internal/provider`, `internal/parity`, `internal/toolcat`, `internal/scheduler`, `internal/defaults`, `internal/firstrun`, `cmd/ass-guard/goconst_constants.go`. The heavy genericizations (profile_check capture loader, extract-profile multi-target, parity suite extractor) are deliberately NOT here — they land beside their dsh counterparts in plans 11-05 and 11-07 (same-file sequential edits, not cross-plan conflicts).
- `internal/ecosys` is legitimately zcode/Claude-Code-shaped (the `.claude/` config-compat surface — that is config compatibility, not mimicry-target leakage) and `internal/profile` legitimately knows profile #1 — both are excluded from the gate, per research §6's rule.
- The gate also bans the inverse sin (CONTEXT discretion): no `provider == "deepseek"` / `profile.Name == "dsh"` switch in mimicry paths — dialect handling keys by capability profile (plans 11-02/11-04 honor it; the gate enforces it structurally).
