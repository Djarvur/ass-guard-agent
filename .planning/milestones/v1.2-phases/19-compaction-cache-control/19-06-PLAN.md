<objective>
Close G-19-1 (operator ruling (b), 2026-09-07): make the overflow retry-once actually recover the PRODUCING turn. Today the forced compaction's marker lands after the producing turn's user message, 19-03's pinned position rule (compactionMarkerIdx, projector.go:303-320) correctly refuses it as that turn's reset point, and the retry re-sends a byte-identical request that deterministically overflows again — recovery reaches the next turn only (19-REVIEW CR-01; found independently by the 19-04 executor in deferred-items). The fix is the operator-approved same-turn marker carve-out: the engine arms a per-turn override on the overflow retry path, and only then does the projector accept a marker whose TurnID equals the projected turn (with no pre-user marker present) as that turn's reset point — the retry projects post-marker: seed = the marker's summary + the turn's own current intent, tail = the budget-fill post-marker span.

Rides along (WR-03, required by the gap's missing list): bound the summarizer input (the rendered post-marker span is char-capped from ContextLimit so the summarize call itself cannot overflow) and stop the per-loop-head re-fire (one threshold-class compaction attempt per turn; today a degraded compaction re-fires at every one of up to 64 loop heads — up to 64 guaranteed-failing near-limit provider calls per turn).

Purpose: ROADMAP criterion 3 ("On a provider overflow error, recovery retries once post-compaction instead of failing the turn") as ruled by the operator — the turn, not merely the session, is rescuable.
Output: projector carve-out + engine retry wiring + WR-03 bounds + a content-sensitive regression battery (payload-size-rejecting fake provider) + replay/reconcile safety pins.
</objective>
