# Plan 03-01 — Tracer: scheduling config + resolver + load-time validation (the "honest config" slice)

## Phase Goal

**As an** operator, **I want to** declare tier→model mappings with time-windows, per-project overrides, fallback chains, and capability profiles in one YAML file, **so that** a tier (heavy/good/light) resolves to a concrete (provider, model) at request time — and an inconsistent config is rejected before any request is served.

## Truths

- Implements D-01 (declarative YAML, viper-loaded, layered global → per-project `.ass-guard/scheduling.yaml` + an embedded zero-config default), D-02 (resolution precedence **time-window → project → global** — the user's explicit reversal; window-wins-outright is structural), D-03 (lazy per-request time evaluation against an IANA zone, `time/tzdata` bundled), D-09 (structured `CapabilityProfile` per model), D-10 (load-time validation rejects inconsistent configs with a named conflict — fail-fast). D-05's config side is included (the explicit per-tier `fallback` array is declared here; the walker that consumes it lands in Plan 03-02).
- Carries SCHED-01 (tier abstraction — `Resolve(tier, …)` returns a concrete `Target`), SCHED-02 (time-windowed substitution, IANA zones, tzdata), SCHED-03 (per-project override falling back to the default), SCHED-06 (capability profiles declared + load-time validation making tier mismatch explicit).
- This is the **TRACER**: a tier resolves end-to-end through the full precedence (peak/off-peak + project override) into a concrete `Target{Provider, Model, BaseURL, Shape, Capabilities, Pricing}` plus an ordered fallback chain — ready to hand to a provider adapter. The provider adapter itself (Phase 1) and the dispatch/fallback-walk (Plan 03-02) are OUT of this plan; the tracer asserts the resolved `Target` is well-formed and the config is honest. This is the resolution half of the scheduling seam; the runtime half is 03-02.

<objective>
Establish the thinnest possible end-to-end scheduling-config + resolver slice that proves the "honest config" guarantee: (1) a declarative `scheduling.yaml` is loaded by viper (layered: embedded default → global → per-project), (2) the config is validated at load time and inconsistent configs are REJECTED with a named conflict (D-10), (3) `Resolve(tier, project, now, capReq)` applies the D-02 precedence (time-window → project → global) with lazy IANA-zone time evaluation (D-03) and returns a concrete `Target` + fallback chain + capability profile. The tracer round-trips a `scheduling.yaml` fixture → resolve(heavy, "myproj", peak-now) returns the window's peak model; resolve(heavy, "myproj", off-peak-now) returns the project/global pick; resolve against an inconsistent config is rejected. No provider SDK, no network — the resolver is a pure function of (config, tier, project, now).
</objective>
