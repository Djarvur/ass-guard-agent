# Plan 03-02 — Runtime dispatch + typed ProviderError + fallback chain + session/update notification

## Phase Goal

**As a** developer, **I want** the turn loop to call `Scheduler.Dispatch(ctx, tier, …)` and have it transparently resolve the tier, call the provider, and — on a transient failure — walk a configured fallback chain so the turn continues on a backup model, **so that** a provider outage degrades gracefully and I see the degradation as a `session/update` notification instead of a failed turn.

## Truths

- Implements D-04 (typed `ProviderError` with `.Kind`: `Transient` | `Structural` | `Exhausted`; the adapter classifies via `ClassifyHTTP`, the scheduler pattern-matches on Kind — `Transient`→walk the chain, `Structural`→report (no retry), `Exhausted`→hard stop), D-05 (explicit per-tier ordered `fallback` list declared in config (Plan 03-01); the walker tries each in order until one succeeds or the list is exhausted), D-06 (an info `ProviderFallback` event emitted to the event bus on each fallback attempt, routed by the Phase-2 ACP adapter as a `session/update` notification — "provider X failed (429), falling back to Y").
- Carries SCHED-04 (fallback chains on provider error/limit with transient-vs-structural classification — N5's silent-retry failure mode engineered out by the typed Kind).
- Introduces `internal/provider/errors.go` (`ProviderError`, `ErrorKind`, `ClassifyHTTP`) — the typed error the Phase-1 adapters WILL return from `Send`/`Stream` when they ship (the intended-interface contract; Phase 1 conforms). This plan defines the type + classifier; Phase 1's adapters call it.
- Extends the Phase-2 event bus (`internal/event`) additively with two new kinds: `ProviderFallback` (info) and `CostCeilingWarn` (warn — type defined here, emitted by Plan 03-03's cost tracker). The bus API is unchanged (Subscribe/Publish); only the catalog grows — the same grow-don't-replace pattern Phase 2 used on Phase 1's seed.
- This plan delivers the **runtime half** of the scheduling seam: `Scheduler.Dispatch` orchestrates resolve → provider call → (on Transient) emit `ProviderFallback` + walk the fallback chain. The provider is a FAKE in tests (canned `Response`/`*ProviderError` per `(provider, model)`); the real adapters land in Phase 1. Circuit breakers (D-07) and cost ceilings (D-08) are wired as no-ops here (Plan 03-03 fills them) — Dispatch has the seams (`breaker.Allow`/`Record*`, `cost.Check`/`Account`) called through interfaces that 03-03 implements.

<objective>
Establish the runtime dispatch seam: a `Scheduler.Dispatch(ctx, tier, project, capReq, messages) (provider.Response, error)` method that resolves the tier (Plan 03-01's Resolver), calls the provider through the Phase-2 semaphore, and on a `KindTransient` failure walks the configured fallback chain (D-05) — emitting a `ProviderFallback` event (D-06) per attempt — until one succeeds or the chain is exhausted; on `KindStructural` it stops immediately and reports (D-04). Introduces `ProviderError` + `ClassifyHTTP` (D-04) in `internal/provider`. The tracer round-trips a fake-provider scenario: primary returns Transient(429) → walker tries fallback-1 → success, with a `ProviderFallback` event observed on the bus; primary returns Structural(401) → walker stops, no event, structural error surfaced.
</objective>
