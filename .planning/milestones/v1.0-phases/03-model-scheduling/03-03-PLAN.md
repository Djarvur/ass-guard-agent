# Plan 03-03 — Circuit breakers + cost ceiling (the safety nets that stop cascades + cost surprises)

## Phase Goal

**As an** operator, **I want** the scheduler to stop a cascading provider outage (circuit breaker) and an unexpected spend spike (cost ceiling), **so that** a failing provider is skipped after N errors and a cost breach degrades gracefully to a cheaper tier instead of producing a surprise bill — both diagnosed from the transcript.

## Truths

- Implements D-07 (circuit breaker using BOTH consecutive-failure AND error-rate trip mechanisms — the most-robust option; per-(provider,model) binding so one bad provider doesn't kill the others; after tripping, open for a cooldown, then a half-open probe tests recovery before fully closing), D-08 (cost ceiling in dollars per time window — operator-intuitive units; the scheduler tracks estimated cost per request from token counts × per-model pricing declared in config, accumulates per window, and on breach degrades to the cheapest configured tier/model + emits a warn `CostCeilingWarn` event; if the degraded tier ALSO hits its ceiling → hard-stop with a clear cost-exhausted error).
- Carries SCHED-05 (circuit breakers + cost ceilings prevent fallback-chain cascading failures and cost surprises).
- The breaker is the sony/gobreaker Closed/Open/HalfOpen state machine distilled in-process (~120 LOC, NO external dep — single-binary). Both mechanisms OR: consecutive trips FAST on hard outage (5 in a row = clearly down); error-rate trips SLOW on degraded performance (>50% over the last 20). Only Transient failures feed the breaker (Structural errors are config bugs, not outages — recording them would mask the real cause).
- The cost tracker uses a fixed calendar-aligned window (MVP — simpler + deterministic-testable via injected `now`; sliding window is a documented v2). Degrade-then-stop, NOT hard-stop-on-first-breach (the ROADMAP goal's "graceful degradation").
- This plan SWAPS the no-op breaker/cost stubs from Plan 03-02's `Scheduler` for real implementations (the seam interfaces defined in 03-02 are implemented here). Every state transition (breaker) and every breach (cost) is logged at Warn to stderr with full diagnostic detail (C5 investigate-and-fix-ready) — the operator can diagnose every trip from the transcript.

<objective>
Deliver the two safety nets. (1) `Breaker` (`internal/scheduler/breaker.go`) — a per-(provider,model) Closed/Open/HalfOpen state machine tripped by consecutive-failure (N=5) OR error-rate (>50% over M=20); cooldown (60s) then half-open probe; recovery closes, failure re-opens. (2) `CostTracker` (`internal/scheduler/cost.go`) — dollars-per-fixed-window accumulation from token counts × pricing; on breach emit `CostCeilingWarn` + degrade to the configured tier; on a second breach hard-stop with `KindExhausted`. (3) Wire both into Plan-03-02's `Scheduler.Dispatch` via `internal/scheduler/safety.go` — the breaker skips open candidates during the fallback walk; the cost tracker's HardStop short-circuits Dispatch with `KindExhausted`. The tracer round-trips: 5 consecutive Transient failures trip a breaker (next Dispatch skips that candidate, logs the trip); accumulating requests past `amount_usd` triggers a CostCeilingWarn + degrade; a degraded-tier second breach returns `KindExhausted`.
</objective>
