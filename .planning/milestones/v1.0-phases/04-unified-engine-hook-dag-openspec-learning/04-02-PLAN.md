# Plan 04-02 — OpenSpec adapter: subprocess hosting + pattern config + mutability registration

## Phase Goal

**As the** agent runtime, **I want to** host the unmodified OpenSpec CLI as a subprocess, surface its stdout into the model's context, declare its handoff patterns + tool shapes in one config, **so that** the engine's dual-signal detector can drive an unmodified OpenSpec workflow and each OpenSpec command's mutability is the single source of truth for context boundaries.

## Truths

- Implements D-13 (OpenSpec as external CLI subprocess — `exec.Command("openspec", args...)`; ass-guard does NOT reimplement OpenSpec), D-14 (`.claude/sdd/openspec.toml` declares `[[patterns]]` + `[[handoff_tools]]`; TOML array-of-tables syntax mirroring the OpenSpec ecosystem), D-15 (each OpenSpec command declares its mutability; `toolcat.EffectiveMutability` + `IsBoundary` consume it unchanged — a mutating command IS a boundary, Phase-2 SESS-02).
- Carries OPEN-01 (shell adapter runs OpenSpec commands as subprocesses, captures stdout/stderr, surfaces stdout as the tool result), OPEN-02 (the `openspec.toml` config declares patterns + handoff tools, seeded from real OpenSpec handoff examples), OPEN-03 (each command declares its mutability shape — the single source of truth for boundaries).
- Depends on 04-01 (the `engine.PatternTable` interface — this plan's `OpenSpecPatternTable` satisfies it) and 04-04 (`toolcat.Catalog.Register` — this plan registers OpenSpec commands). The TOML parser dependency (`github.com/BurntSushi/toml`) is added here, isolated to this package (RESEARCH §2.3 reconciliation).

<objective>
Ship the OpenSpec hosting adapter: (1) `LoadConfig(path) (*OpenSpecConfig, error)` parses `openspec.toml` with BurntSushi/toml — the `[[patterns]]` (text-regex → action) and `[[handoff_tools]]` (tool-call name → action) tables + a `[commands]` map of command → mutability; compile each pattern regex once at load; (2) `Adapter.Run(ctx, command, args) (stdout, stderr string, err error)` executes `exec.Command("openspec", ...)` with ctx-timeout + stdout/stderr capture; if `openspec` is not on PATH, return a structured `ErrOpenSpecNotFound` (the engine routes this to learning `ask`); exit-code contract: 0 = success (stdout surfaced), non-zero = error with stderr; (3) `RegisterTools(catalog, cfg)` registers each declared command as a `toolcat.Tool` with its mutability via `Catalog.Register`; (4) `OpenSpecPatternTable` implements `engine.PatternTable` (MatchText/MatchTool) over the compiled patterns — bridging the TOML config to the engine's dual-signal detector (D-02). Seeded defaults ship as `seeded.toml`. The subprocess tests use a stub `openspec` script on PATH (a tiny shell script in testdata that echoes + exits a coded value); real-`openspec` tests run only when `ASSGUARD_OPENSPEC_BIN=1` is set (gated skip otherwise).
</objective>

// The TOML config shape (D-14 — [[patterns]] + [[handoff_tools]] + [commands]).
type OpenSpecConfig struct {
    Patterns     []PatternEntry     `toml:"patterns"`
    HandoffTools []HandoffToolEntry `toml:"handoff_tools"`
    Commands     map[string]CommandShape `toml:"commands"` // command name → mutability
}
type PatternEntry struct {
    ID     string `toml:"id"`
    Regex  string `toml:"regex"`   // matched against the assistant text
    Action string `toml:"action"`  // continue | hook | ask | wait
}
type HandoffToolEntry struct {
    ID     string `toml:"id"`
    Tool   string `toml:"tool"`    // the tool-call name (D-02 second signal)
    Action string `toml:"action"`
}
type CommandShape struct {
    Mutability string `toml:"mutability"` // "mutating" | "read-only" (D-15 / OPEN-03)
}

// Adapter is the subprocess host (D-13 / OPEN-01).
type Adapter struct {
    Binary string // default "openspec"; overridable for tests
    Log    *slog.Logger
}
func (a *Adapter) Run(ctx context.Context, command string, args ...string) (stdout, stderr string, err error)

// OpenSpecPatternTable bridges the TOML config to engine.PatternTable (D-02).
type OpenSpecPatternTable struct {
    textPatterns []compiledPattern  // regex + id + action
    handoffTools map[string]Action  // tool name → action
}
func (t *OpenSpecPatternTable) MatchText(text string) (id string, action engine.Action)
func (t *OpenSpecPatternTable) MatchTool(name string) (id string, action engine.Action)

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| operator → openspec.toml → engine config | Operator-authored TOML crosses here; a malformed regex/action/mutability could misroute the engine or misclassify a boundary. |
| engine → openspec subprocess | ass-guard launches an external process; a ctx cancel must reach the child (no orphan); stderr is operator-visible, not model-visible. |

## STRIDE Threat Register (canonical Phase-4 IDs)

| Threat ID | Category | Component | Disposition | Mitigation |
|-----------|----------|-----------|-------------|------------|
| T-04-06 | Availability / resource exhaustion | OpenSpec subprocess orphaned on ctx cancel (zombie child) | mitigate | Run uses `exec.CommandContext` — ctx cancel signals+kill the process; T2 Test 3 asserts cancellation returns within 200ms with no orphan |
| T-04-06b | Information disclosure | command stderr surfaced to the model as if it were a result | mitigate | Run returns stdout as the tool result ONLY on exit 0; stderr is captured for diagnostics but surfaced to the model only on failure (T2) |
</threat_model>
