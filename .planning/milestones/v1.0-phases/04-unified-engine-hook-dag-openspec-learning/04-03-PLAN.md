# Plan 04-03 — Hook-DAG executor (the "forgotten routine" engine)

## Phase Goal

**As an** SDD practitioner, **I want** the "forgotten routine" (tests, lint, review, memory after implement; improvement proposals after a phase) to run automatically after each stage via a configurable DAG, **so that** I never skip the routine and a hook failure never silently blocks my workflow.

## Truths

- Implements D-06 (declarative YAML hook config — `gopkg.in/yaml.v3` directly, mirroring `internal/scheduler/load.go`'s deviation from viper; layered embedded-default → operator-override), D-07 (hand-rolled in-process DAG executor, ≤300 LOC core — Temporal/Argo/Windmill rejected as server products), D-08 (four step kinds: run-command / send-prompt / fresh-context / wait), D-09 (the seeded set ships as a default config), D-10 (on-failure: halt | continue | ask on every hook + step), D-11 (provenance prevents loops — a hook cannot re-trigger its triggering stage without `allow_reentrant: true`), D-12 (send-prompt IS a turn through the Session Core; fresh-context owns its window via boundary semantics).
- Carries HOOK-01 (configurable DAG executor runs the four step kinds in any order), HOOK-03 (on-failure on every hook — never silently block), HOOK-04 (provenance tagging structurally prevents infinite loops), HOOK-05 (send-prompt IS a turn; fresh-context IS a boundary). HOOK-02 (the seeded set content) is authored here as `seeded.yaml`; the WIRING (the engine launching the post-implement/post-phase DAG) lands in 04-05.
- This plan ships a **standalone, fully-tested `internal/hookdag`** with NO dependency on `internal/engine`, `internal/session`, or `internal/provider`. The executor takes injected interfaces (`CommandRunner` for run-command, `TurnRunner` for send-prompt, `BoundaryOpener` for fresh-context) so the unit tests are pure + deterministic. 04-05 wires the real implementations; here they are fakes.

<objective>
Ship the hand-rolled DAG executor that runs the "forgotten routine": (1) load hook config from YAML (layered: embedded `seeded.yaml` default → operator overlay) into typed `Hook`/`Step` structs; (2) `Executor.Execute(ctx, hook, provenance) Result` walks the hook's steps in declared order, dispatching each by kind (run-command via `exec.Command`+exit-code contract; send-prompt via the injected TurnRunner = a real turn; fresh-context via the boundary opener; wait via sleep/condition); (3) on any step failure apply the declared `on-failure` (halt stops the chain; continue logs + proceeds; ask surfaces a HookProgress event and suspends); (4) provenance loop prevention — refuse to launch a hook whose `(name, triggerStage)` is already in-flight unless `allow_reentrant: true`; (5) emit `HookProgress` events at every step boundary → bus. The executor core (walk + dispatch + provenance + on-failure) is ≤300 LOC; the per-step impls + config + tests are additional. Every behavior is tested with fakes (a recording CommandRunner, a fake TurnRunner) — no real shell, no live provider.
</objective>

type OnFailure string  // "halt" | "continue" | "ask"
const (
    OnFailureHalt     OnFailure = "halt"
    OnFailureContinue OnFailure = "continue"
    OnFailureAsk      OnFailure = "ask"
)

// StepKind discriminates the four step types (HOOK-01 / D-08).
type StepKind string
const (
    StepRunCommand   StepKind = "run-command"
    StepSendPrompt   StepKind = "send-prompt"
    StepFreshContext StepKind = "fresh-context"
    StepWait         StepKind = "wait"
)

type Step struct {
    Name       string        `yaml:"name"`
    Kind       StepKind      `yaml:"kind"`
    OnFailure  OnFailure     `yaml:"on_failure"`        // defaults to the hook's
    Command    string        `yaml:"command,omitempty"` // run-command: the shell argv
    Args       []string      `yaml:"args,omitempty"`
    Prompt     string        `yaml:"prompt,omitempty"`  // send-prompt: the turn prompt
    Duration   string        `yaml:"duration,omitempty"`// wait: Go duration string
}

type Hook struct {
    Name           string   `yaml:"name"`
    Trigger        string   `yaml:"trigger"`          // "post-implement" | "post-phase" | custom stage
    Steps          []Step   `yaml:"steps"`
    OnFailure      OnFailure `yaml:"on_failure"`       // default for steps that omit theirs
    AllowReentrant bool     `yaml:"allow_reentrant"`   // D-11 opt-in
}

// Provenance identifies the stage + turn that triggered this hook (HOOK-04).
type Provenance struct {
    HookName     string
    TriggerStage string
    SourceTurnID string
}

// The three injected seams (fakes in tests; real in 04-05).
type CommandRunner interface {
    // Run executes the command, returns stdout, stderr, exit code.
    Run(ctx context.Context, command string, args []string) (stdout, stderr string, exitCode int, err error)
}
type TurnRunner interface {
    Run(ctx context.Context, prompt []session.ContentBlock) (stop string, err error) // send-prompt IS a turn (HOOK-05)
}
type BoundaryOpener interface {
    OpenBoundary(ctx context.Context, cause string) error // fresh-context owns its window (HOOK-05)
}

// Executor is the hand-rolled DAG executor (D-07). The only mutable state is
// the provenance in-flight set (HOOK-04), guarded by a mutex.
type Executor struct {
    Bus       *event.Bus
    Log       *slog.Logger
    Commands  CommandRunner
    Turns     TurnRunner
    Boundaries BoundaryOpener

    mu        sync.Mutex
    inFlight  map[string]struct{} // key = HookName + "|" + TriggerStage
}
