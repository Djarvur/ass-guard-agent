# Plan 04-05 — Integration: engine ↔ hook-DAG ↔ OpenSpec ↔ real tool exec (zero-continue end-to-end)

## Phase Goal

**As an** SDD practitioner, **I want to** run an unmodified OpenSpec scenario through ass-guard and watch it advance stage-to-stage with zero "continue" taps while the seeded hook set (test+lint+review+memory after implement; proposals after a phase) runs automatically, **so that** the project's reason to exist is demonstrably met.

## Truths

- Wires D-01 (engine post-turn observer) into the ACP serve layer (acp_serve.go:171 — `sess.Prompt`), D-12 (hook-DAG send-prompt orchestrates turns via the Session Core), D-09 (the seeded hook set from 04-03 is the default), D-13/D-15 (the OpenSpec adapter + mutability registration from 04-02 are loaded at startup), D-21 (the real tool executor from 04-04 is injected).
- Carries ENG-05 (an unmodified OpenSpec workflow runs end-to-end with zero continue taps — the success bar; this plan is the integration that PROVES it), HOOK-02 (the seeded set is wired: the engine's ActionHook launches the post-implement / post-phase DAG from the 04-03 default config), OPEN-02 (the full pattern/handoff tables seeded from real OpenSpec handoff examples in 04-02's seeded.toml are loaded + drive the engine).
- This plan is INTEGRATION: it edits `cmd/ass-guard/acp_serve.go` (inject the real toolExec; wrap `sess.Prompt` with the engine; load the OpenSpec config + register tools; load the hook config; wire the engine's ActionHook to the hook-DAG executor, ActionAsk to the learning store) and adds the engine's action-dispatch (continue/hook/ask) to `internal/engine/observe.go` (the 04-01 tracer stubbed these; here they dispatch to real seams). The end-to-end test uses a fake provider + a stub `openspec` script on PATH + the real hook-DAG + a real Session/Manager — no live network.

<objective>
Wire the five Phase-4 packages into one end-to-end zero-continue loop and prove it: (1) `acp_serve.go` constructs the engine + loads openspec.toml + registers OpenSpec commands (mutability) + loads hooks.yaml + injects the real tool executor into the Session; (2) the engine's `Observe` wrapper, after `sess.Prompt` returns end_turn, dispatches its Decision — ActionContinue re-enters `sess.Prompt` with the next-stage prompt; ActionHook launches the matching hook-DAG via `hookdag.Executor` (with real CommandRunner/TurnRunner/BoundaryOpener seams); ActionAsk consults the learning store (Lookup → use, else ask); (3) the end-to-end test runs a scripted 3-stage OpenSpec scenario: stage 1 assistant text matches the "impl-complete" pattern → engine continues → stage 2 → pattern → continue → stage 3 → end_turn (no match) → loop exits. The seeded post-implement hook fires once (its run-command steps run against a stub). Zero manual taps. Structural safety: a turn with no match → no continuation.
</objective>

type ActionDispatcher interface {
    // Continue injects the next-stage prompt (a real Session.Prompt turn).
    Continue(ctx context.Context, dec Decision) (stop string, err error)
    // Hook launches the matching hook-DAG (hookdag.Executor.Execute).
    Hook(ctx context.Context, trigger string, prov hookdag.Provenance) hookdag.Result
    // Ask consults the learning store; if a learned answer exists, apply it; else
    // emit a session/update asking the user + return ErrAskPending.
    Ask(ctx context.Context, situation string) (answer string, err error)
}

// The real dispatcher (constructed in acp_serve.go, used by Observe).
type acpDispatcher struct {
    Runner    sessionTurnRunnerLike   // the Session Core turn runner (continue)
    Hooks     *hookdag.Executor       // hook dispatch
    TriggerMap map[string]string      // action "hook" → hook trigger name (from pattern config)
    Learning  *learning.Store         // ask-once-remember
    Bus       *event.Bus
}
