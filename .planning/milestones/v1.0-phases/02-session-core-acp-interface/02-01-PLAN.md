# Plan 02-01 — Tracer: ACP v1 stdio server (initialize → session/new → session/prompt → streamed session/update)

## Phase Goal

**As a** developer using Zed, **I want to** spawn ass-guard via ACP and watch a prompt stream token-by-token, **so that** ass-guard is usable as a daily coding agent inside the IDE.

## Truths

- Implements D-14 (hand-rolled JSON-RPC framing ~150 LOC — `bufio.Reader` over stdin, mutex-guarded writer to stdout, `Message` envelope, notification-vs-request distinction via `*int` ID), D-15 (single reader goroutine + per-prompt turn goroutine; method→handler map), the ACP-05 framing resolution, and the VERIFIED-FACTS #3 wire shape (`agentCapabilities` field name, integer `protocolVersion`, newline-delimited framing, `session/update` notification has no `id`).
- Carries ACP-01 (stdio JSON-RPC server, stdout=frames/stderr=logs), ACP-02 (lifecycle methods `initialize`, `session/new`, `session/prompt` — the v1 method set), ACP-04 (end-to-end streaming — provider output flows to `session/update` with NO full-turn buffering), ACP-05 (framing resolved + documented).
- This is the TRACER: a real `initialize → session/new → session/prompt` round-trip with ONE streamed `agent_message_chunk` `session/update` notification observed before the `session/prompt` response. The provider is a STUB returning canned chunks (real provider streaming is Plan 02-04; real Session Core turn loop is Plan 02-02). This plan wires the ACP transport end-to-end against a stub; subsequent plans replace the stub.

<objective>
Establish the thinnest possible end-to-end ACP v1 server that proves the transport seam: a stdio JSON-RPC server with hand-rolled newline-delimited framing, the canonical method set (`initialize`, `session/new`, `session/prompt`, `session/cancel`, `session/load`, `logout`, `session/set_mode`), and a streaming `session/update` notification path from a stub turn loop to the client. The tracer round-trips `initialize → session/new → session/prompt` against an in-process mock client over `io.Pipe` (pattern from `spikes/03-acp-handshake/`), observing at least one `session/update` notification before the `session/prompt` response. This is NOT the real Session Core (Plan 02-02), NOT real provider streaming (Plan 02-04), and NOT real subagent dispatch (Plan 02-05) — those plug in after the transport seam is proven.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| stdin → server | Untrusted JSON-RPC input crosses here (the editor, or anything that can write to the process stdin) |
| server → stdout | Protocol output (frames) crosses here; stdout pollution breaks the protocol |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-01 | Tampering | framer (stdin parsing) | mitigate | `readFrame` returns parse errors as `-32700` JSON-RPC error responses; server keeps reading after malformed frames (Task T2 Test 6) |
| T-02-02 | Tampering | stdout (transport discipline) | mitigate | `Writer` is the sole stdout writer; `log.SetOutput(os.Stderr)`; transport-discipline test asserts stdout is clean (Task T2 Test 5, Task T3) |
| T-02-03 | Information disclosure | error responses | mitigate | error messages scrubbed via `redact.ScrubError` before marshaling into `RPCError.Message` (C2 pattern) |
| T-02-04 | DoS | leaky goroutines on cancel | mitigate | every turn goroutine selects on `ctx.Done()`; `session/cancel` cancels ctx; test asserts goroutines exit (Task T2 Test 4, `-race`) |
| T-02-05 | Spoofing | session/cancel from non-owner | accept | v1 has no auth tier (PROJECT.md safety model); any stdin writer can cancel — accepted per the "manual cancellation is the only safety mechanism" principle |
</threat_model>
